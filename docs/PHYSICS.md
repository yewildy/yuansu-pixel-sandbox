## 1. 仿真模型总述（Simulation Model）

### 1.1 元胞自动机（Cellular Automaton）
- 网格：$W \times H = 320 \times 180 = 57{,}600$ 格，四邻域（von Neumann）为默认；粉末/液体/气体移动使用 3–5 邻域（见 §5）。
- 每格状态为一个定长记录：

| 字段 | 类型 | 说明 |
|---|---|---|
| `element` | `Uint8Array` | 元素 ID（1–30，见 §4） |
| `temp` | `Float32Array` | 温度，单位 **°C**，范围 $[-200, 2000]$（**必须浮点**，见 §13.4 与审查 F15） |
| `age` | `Uint16Array` | 寿命/年龄计数器（tick），语义随元素定 |
| `flags` | `Uint8Array` | bit0 = 本帧已移动标记；bit1 = 本帧已反应标记 |

- 采用 **Structure-of-Arrays（SoA）** 布局，主循环零 `new`（见 `DESIGN.md` §9.2）。

### 1.2 tick 定义
- 仿真以**固定步长**推进：`TICK_HZ = 60`，即 $dt = 1/60\ \text{s} \approx 16.67\ \text{ms}$。
- 渲染与仿真解耦：使用累加器（accumulator）模式。每帧 `accumulator += realDt`，`while (accumulator >= dt) { step(); accumulator -= dt; }`，并设 `MAX_SUBSTEPS = 4` 防止螺旋死亡（掉帧时丢步而非卡死）。

### 1.3 每 tick 更新顺序（Update Order）
严格按以下顺序执行（顺序影响结果，不可调换）：

```
1. clearFlags()                          // 清空 flags 的所有 bit（实现用递增 tickId 的 moveStamp/reactStamp 取代，见 ADR-0001/0003）
2. movePass()                            // 物态移动（自下而上，x 扫描方向逐帧交替）
2b. airPass()  ★新增                     // 空气专用对流/浮力/风（§5.4；隔帧执行；见 docs/PHYSICS-AIR.md）
3. reactionPass()                        // 化学反应（按 §9 优先级；含 §9.6 耗氧）
4. lifePass()                            // 生命/植物/病毒（严格生态，§10；见 docs/PLANT-MODEL.md）
5. thermalPass()                         // 导热计算 → nextTemp（§6；含空气-空气双轨配对）
6. phasePass()                           // 相变判定（读 nextTemp，写 element）（§7）
7. relaxAndClamp()                       // 环境弛豫 + 顶部天空热沉 + 温度钳制（§6.3）
8. swap temp ↔ nextTemp
9. agePass()                             // 全格 age++（有上限者；含 §9.3 燃料残灰）
10. windPass()                           // 轻质粉末漂移（§11；气体平流在 movePass 内）
```

> **`airPass` 位置理由**：置于 `movePass` **之后**——本帧已被物质置换的空气格带 `moveStamp==tick`，不会被同一 tick 再对流一次（防重复）；置于 `thermalPass` **之前**——空气搬运的温度本帧即能参与导热扩散。

### 1.4 扫描方向与「已移动」防重复
- **自下而上**：`movePass` 按 `y = H-1 → 0` 遍历。理由：粉末/液体向下运动，自下而上处理可让下方先落定，避免同帧内一个粒子被移动多次。
- **水平方向逐帧交替**：偶数 tick 从左到右（`x = 0 → W-1`），奇数 tick 从右到左（`x = W-1 → 0`）。这是**消除方向偏置**的关键——否则所有液体都会倾向一侧漂移。交替是免费且确定的，不引入随机。
- **「本帧已移动」标记**：任一格被写入（移动/交换/生成）后，目标格的 `flags.bit0 = 1`。`movePass` 只处理 `bit0 == 0` 的格。防止「A 移到 B，B 同帧又移走」导致的穿越与双跳。**实现用递增 `moveStamp[i] = tickId` 取代每帧清 flag；`airPass` 的空气移动复用同一 `moveStamp`（不新增数组）**。
- 同类 `reactionPass` 使用 `flags.bit1`（实现为 `reactStamp`），防止同一格一帧内触发多条反应。

### 1.5 确定性
- 所有「随机」均为**确定性哈希**：以 `(x, y, elementId, tick)` 为输入生成 $r \in [0,1)$，避免 `Math.random()` 导致的不可复现。
- 提供全局 `SEED` 常量（默认 1337）；更换 SEED 即更换整局随机序列，便于「同一初始条件 → 同一结果」与调试/单测（满足 `DESIGN.md` R4）。

## 2. 单位与尺度约定（Units & Scale）

| 量 | 单位 | 约定值 | 说明 |
|---|---|---|---|
| 空间 | 格（cell） | 1 格 $\approx 6\ \text{mm}$ | 使 320 格宽 $\approx 1.92\ \text{m}$、180 格高 $\approx 1.08\ \text{m}$，桌面级沙盘尺度（近似） |
| 时间 | tick | $1\ \text{tick} = 1/60\ \text{s}$ | 固定步长 |
| 温度 | °C | `Float32`，$[-200, 2000]$ | 环境温度 $T_{amb} = 20$ |
| 密度 | kg/m³（相对） | 见 §4 | 仅用于位移比较（决定浮沉/沉浮/置换），不参与动力学积分。**`AIR` 的 density 1.2 为参考值，因 `target===1` 短路而不参与通用位移**（§4.1 注¹） |
| 质量 | 归一化 | 每格质量 = 1（无量纲） | 「物质守恒」= 非 `AIR` 格数（§13）；总格数恒为 $W\times H$ |
| 比热 | J/(kg·K) | 见 §4 | 用于热弛豫加权；本作以「相对热惯性」使用（近似）。导热采用「双轨配对系数」，空气-空气用 `AIR.SELF_K`（§6.1） |
| 导热系数 | 无量纲 $k \in [0,1]$ | 见 §4 | 归一化「导热快慢」，非真实 W/(m·K)（近似） |
| 时间率 | 每 tick 概率 $p \in [0,1]$ | 见 §7 | 反应/相变以每 tick 概率表达；平均耗时 $= 1/p$ tick |

> **尺度说明（近似）**：本作不做真实量纲换算，密度/比热/导热保留真实相对序（水 1000 < 岩浆 2800；金属导热最快），但**数值经归一化**以便直接编码。凡「近似」处均已在表中标注。

## 5. 物态移动规则（Movement Rules）

> 通用前置：目标格可进入的条件 = 目标为 `AIR`，**或** 目标为可移动流体且密度更低（则**交换**两格）。静态固体（`movable=false`）永不被置换。所有 `enterable*` 判定对 `target === 1`（AIR）直接短路放行，故空气的 density 数值不参与该分支（§4.1 注¹）。
> 所有概率判定用确定性哈希（§1.5）。

### 5.1 粉末（Powder：SAND/SOIL/SALT/DUST/SNOW/ASH/GUNPOWDER/SEED）
按优先级尝试（命中即停）：

1. **正下方** `(x, y+1)`：若可进入 → **必然下落**（$p = 1.0$）。
2. **斜下方** `(x-1, y+1)` 与 `(x+1, y+1)`：先按哈希随机决定左右优先序，对每个可进入的斜格以概率

$$p_{\text{diag}} = \texttt{repose}$$

尝试移动。`repose` 越高越易滑动 → 堆越平；越低越陡。**休止角由 `repose` 涌现**，无需显式角度：
   - `SAND` repose 0.85 → 接近水平摊开
   - `SNOW` repose 0.35 / `DUST` 0.40 → 陡而松散的小堆
3. 粉末不主动上升。

**落速**：粉末每 tick 至多移动 1 格（无加速），保证可预测（支柱 1）。

### 5.2 液体（Liquid：WATER/OIL/LAVA/ACID/LN2/SPRING）
按优先级：

1. **正下方** 可进入 → $p = 1.0$ 下落。
2. **斜下方** 两个方向 → 各 $p = \texttt{mobility}$。
3. **水平** `(x±1, y)` → $p = \texttt{mobility} \times 0.8$（水平铺展/找平）。
4. **上浮**：若 **正下方**是密度更高的液体（如 OIL 在 WATER 下）→ 交换（浮力）。

**黏度** $= 1 - \texttt{mobility}$：`LAVA` mobility 0.35 → 缓慢黏稠；`WATER` 0.90 → 快速铺展。
**分层**：由密度差自然分层——`OIL(900)` 浮于 `WATER(1000)` 之上；`LAVA(2800)` 沉于水底；`LN2(807)` 浮于一切常液体之上。

### 5.3 气体（Gas：STEAM/SMOKE/FIRE/GAS）
按优先级：

1. **风力平流**（先于浮力，§11）：以 $p = \texttt{wind.strength} \times \texttt{windFactor}$ 沿风向移动 1 格。
2. **浮力上升** `(x, y-1)` 或斜上 → $p = \texttt{mobility}$（因所有气体密度 $< 1$，默认上升；密度越小的气越急）。
3. **随机扩散**：水平方向 `(x±1, y)` → $p = \texttt{mobility} \times 0.5$，方向由哈希定。
4. 气体遇顶边（$y=0$ 再向上）→ **从系统移除**（"vented"，§13.3）。

`FIRE` 特殊：除上述外，还会按 §9 点燃邻格燃料；上升更快（mobility 0.8）。

### 5.4 空气运动（Air Motion）★新增（修复 B3：无对流、热空气不上升）
空气 `movable = no`，**不经** §5.1–§5.3 的通用移动通道；其运动完全由独立的 `airPass` 提供（`src/core/air.js`，见 `docs/PHYSICS-AIR.md §5/§6`）：

1. **驱动判据**：令 $\Delta = T - T_{amb}$。仅当 $\Delta > \texttt{AIR.BUOY\_DT}$（热，上浮）或 $\Delta < -\texttt{AIR.COLD\_DT}$（冷，下沉）时空气才移动；否则**完全不动**（均匀室温空气零成本）。
2. **上浮/下沉**：与正上方/正下方的 `AIR` 格以概率 $p = \mathrm{clamp}\bigl(\frac{|\Delta|-\texttt{BUOY\_DT}}{\texttt{AIR.BUOY\_SCALE}}, 0, \texttt{AIR.BUOY\_P\_MAX}\bigr)$ 交换。**交换即附带温度交换**（§13.1），故热空气上浮时把热量一并带走——这就是"对流换热"的全部实现。
3. **隔帧**：`airPass` 每 `AIR.PASS_INTERVAL = 2` tick 执行一次；最大位移速度 $= \texttt{BUOY\_P\_MAX} / \texttt{PASS\_INTERVAL} = 0.6/2 = \mathbf{0.3}$ 格/tick（≈18 格/s）。
4. **风平流**：风只搬运"携带热量"的空气格（$|\Delta| > \texttt{AIR.WIND\_MIN\_DT} = 1$ °C），纯室温空气不搬运（画面等价、成本可控）；受风敏感度 `AIR.WIND_FACTOR = 0.5`。
5. **烟囱效应**：竖向热空气柱被两侧固体夹持、顶部开放、底部有持续热源且侧面可进风时，形成自持上升气流（定量条件见 `docs/PHYSICS-AIR.md §5.5`）。

> 实现位置：`Engine.step` 第 2 步，紧随 `movePass` 之后、`reactionPass` 之前——保证被物质置换过的空气格本帧不再对流（防重复），且本帧搬运的温度能参与随后的导热。

## 6. 热学模型（Thermal Model）

### 6.1 离散导热公式
对每个非 `AIR` 格 $i$，与其 4 邻域 $N(i)$ 交换热量。使用双缓冲 `nextTemp`：

$$T_i' = T_i + \alpha \sum_{j \in \{E,S\}} K_{ij}\,\bigl(T_j - T_i\bigr)$$

**配对系数 $K_{ij}$ 采用「双轨制」**（`docs/PHYSICS-AIR.md §4.1`）：

$$K_{ij} = \begin{cases} \texttt{AIR.SELF\_K} = 0.5, & \text{两格皆 AIR（代表空气湍流混合增强）}\\ \dfrac{k_i + k_j}{2}, & \text{其余配对（沿用原式）} \end{cases}$$

- $\alpha = \texttt{HEAT\_COUPLING} = \mathbf{0.005}$（全局热耦合系数）
- $k$ = 各元素 `conductivity`（§4.1）
- **稳定性约束**：单格单 tick 增益系数 $= \alpha \cdot 4 \cdot \max(K) = 0.005 \times 4 \times \texttt{SELF\_K} = 0.01 \ll 0.5$，满足显式差分稳定条件，绝不振荡发散。
- **实现注记（每对只算一次 + 近平衡跳过）**：只与右、下两个邻居交换（$j \in \{E, S\}$）。两格皆为 AIR 时，先判 $\lvert \Delta T\rvert < \texttt{AIR.CONDUCT\_EPS} = 0.25$ °C 则**跳过**——一张均匀室温的空画布全部跳过，成本回落到 ≈0（保住"空场快速跳过"的收益）。

> ⚠️ **α 与空气 k 的联合标定（审查 F01 修正 · 致命级；本版升级为双轨系数）**
> 首版取 $\alpha = 0.12$、空气 $k = 0.05$，则岩浆（1200 °C）与一个空气格的热交换高达 **−24.8 °C/tick**，
> 4 邻格合计 **−99 °C/tick** → **约 5 tick（0.08 秒）就把岩浆降到凝固点 700 °C**。岩浆根本来不及与任何东西交互，整个"岩浆玩法"直接失效。
>
> 修正历程：先取 $\alpha \to 0.005$、空气 $k \to 0.002$（近绝热）；随后为修复 B1/B2（空气不导热、空气当热库），空气升级为真实元素，
> 空气 $k$ 回升至 $\mathbf{0.05}$，但**固-气/液-气配对仍用 $K=(k_i+k_j)/2$**（与首版同量级），并**单列 `AIR.SELF_K = 0.5` 仅用于空气-空气对**，
> 使"空气内部能横向传热"与"岩浆不被空气秒抽干"这对矛盾同时成立。标定后岩浆-空气 $K = (0.30+0.05)/2 = 0.175$（较 0.151 仅 +16%），F01 保留。
>
> 标定后关键交互速率验证：
>
> | 交互 | 每 tick 温差变化 | 到目标耗时 |
> |---|---|---|
> | 岩浆 → 空气散热（3 个空气邻格） | ≈ −2.7 °C | 1200→700 °C：**≈ 2.2 s** ✅（F01 保留） |
> | 岩浆 加热 水 | ≈ +2.1 °C / 邻格 | 20→100 °C：**≈ 0.65 s** ✅（淬水剧烈，符合预期） |
> | 岩浆 加热 冰（−10 °C） | ≈ +1.8 °C / 邻格 | −10→0 °C：**≈ 0.6 s** ✅ |
> | 火焰 加热 木柴 | ≈ +1.2 °C / 邻格 | 22→300 °C：**≈ 3.7 s**（另有 §9 概率点火，不依赖此路径） |
> | 冰 在 20 °C 空气中 | ≈ +0.083 °C | −10→0 °C：**≈ 2.25 s** ✅（F15 保留） |

### 6.2 边界与空气
- 网格外视为**绝热**（无热流出去/进来），热交换仅在网格内；唯一热出口是顶部天空层（§6.3）。
- `AIR` 参与导热（$k = \mathbf{0.05}$，与 §4.1 一致；原 §6.2 误写 0.05 而 §4.1 写 0.002，本版统一为 0.05），使空气成为**弱导热介质**；空气-空气对用 `AIR.SELF_K`（§6.1）。

### 6.3 向环境温度弛豫（Cooling / Relaxation）+ 顶部天空热沉
每次导热后，向 $T_{amb}=20$°C 弛豫：

$$T_i' \leftarrow T_i' + r_{c(e_i)} \cdot \bigl(T_{amb} - T_i'\bigr)$$

- $r_{c}$ 按类别取基础值：

| 类别 | `envRelax` 基础值 | 说明 |
|---|---|---|
| AIR（空气） | **0.0005** | **原 0.10 → 0.0005**（半衰期 ≈1386 tick ≈23 s）。原 0.10（暴露 ×2 = 0.20/tick）会把 600 °C 空气 30 tick 压回 21 °C（$(1-0.2)^{30}\approx0.0012$），正是缺陷 B2 的精确来源。空气**不再是热库** |
| gas | 0.004 | 气体较慢冷（原 0.02 会让蒸汽一冒出来就冷凝，见审查 F02） |
| liquid | 0.0005 | 液体极慢冷（原 0.005 会让岩浆在 0.7 s 内凝固） |
| solid/powder | 0.001 | 固体极慢冷 |

- **暴露加成**：若该格的 4 邻域中**至少一个为 `AIR`**，则 $r_{c} \leftarrow r_c \times \texttt{EXPOSED\_RELAX\_MULT}$，其中 `EXPOSED_RELAX_MULT = 2.0`。理由：裸露表面散热快于内部（近似）。**注意：AIR 格本身不适用暴露加成**（空气的"暴露"无物理意义）。
- **顶部天空热沉（新增，唯一热出口）**：顶部 `AIR.SKY_ROWS = 2` 行内的 **AIR 格**按 $T \leftarrow T + \texttt{AIR.SKY\_RELAX} \cdot (T_{amb}-T)$ 散热（`SKY_RELAX = 0.02`/tick，时间常数 ≈50 tick）。只带走"热"，不删除空气格（与气体逸出区分）；固体/液体在顶行不散热。形成"热空气上升→到顶散热→变重下沉"的自然对流闭环。

**效果示例（近似）**：一块 500 °C 的石头放入空气，暴露面按 $0.001 \times 2 = 0.002$ 弛豫；同时热量现可经空气导热扩散并被对流带到天空层，故约 **5–10 s** 回落（比旧模型的 ≈19 s 更快，因空气不再是绝热层）。

### 6.4 相变潜热的近似处理（Latent Heat Approximation）——**近似**
真实相变需吸收/释放潜热（冰融化 $334\ \text{kJ/kg}$），本作**不引入第二温度变量**，改用**温度平台钳制（plateau clamp）法**近似：

- 当某格进入相变阈值区（如冰处于 $[0, +2]$°C 且判定将融化），将其温度**钳在相变点** $T_{pc}$，并累计内部进度 `latent++`；
- 若在平台期内被重新加热/冷却出阈值区，则 `latent` 按 $1$ tick 衰减，相变不发生；
- 仅当「平台停留累计」超过阈值 $\texttt{LATENT\_TICKS}$ 时，才真正切换物态，并把温度设为 $T_{pc}$。

| 相变 | 平台温 $T_{pc}$ | `LATENT_TICKS` | 说明 |
|---|---|---|---|
| ICE → WATER | 0°C | 12 | 融化需持续 12 tick 供给热量（近似潜热） |
| WATER → STEAM | 100°C | 8 | 沸腾需持续供热 |
| STEAM → WATER | 100°C | 6 | 冷凝放热 |
| LAVA → STONE | 700°C | 10 | 凝固释放潜热（近似） |
| SNOW → WATER | 0°C | 4 | 雪比冰更快融（近似，结构疏松） |
| LN2 → AIR | -196°C | 6 | 气化吸热 |

> **近似理由**：格级仿真若严格追踪焓值需额外 `Float32` 场与更复杂的稳定性处理，收益低。平台法在视觉与手感上等价，且**完全确定、可编码**。所有相变点均在 §7 给概率，平台法只决定「切换时刻的能量门槛」。

**平台法与 §7 概率的关系（消除双重定义歧义 · 审查 F04）**
两者是**串联的两道闸**，不是二选一：

```
每 tick 判定某格是否相变：
  ① 能量闸：latent ≥ LATENT_TICKS ？
     · 处于阈值区（|T − T_pc| ≤ 2）时：温度被钳在 T_pc，latent++
     · 越过阈值但不在窗口内（如 200 °C 的水）：latent 每 tick +1（不再钳温、不再吸潜热 —— 近似）
     · 退回阈值另一侧：latent 每 tick −1（下限 0）
  ② 随机闸：rnd() < p(T) ？   ← p 见 §7
  ① 且 ② 同时通过 → 真正切换物态，latent 归零
```

- **窗口内钳温**是潜热的物理表达：格子在相变点"停留"而不升温，说明热量被用来改变物态而非提高温度。
- **窗口外不钳温**（如过热到 200 °C 的水）：直接按 §7 概率蒸发，不吸收潜热。这是**近似** —— 真实的水一旦超过沸点会剧烈闪蒸，本作以"概率随温度上升"来表达，视觉与手感等价。
- 由此，「水多久变汽」= `max(LATENT_TICKS_BOIL, 1/p)` tick，两段都可调。

## 7. 相变表 + 量化概率（Phase Transitions）

> 每格每 tick 以概率 $p$ 判定；平均耗时 $= 1/p$ tick $= 1/(60p)$ 秒。所有概率均与温度相关，曲线形状见说明。

### 7.1 水 → 蒸汽（WATER → STEAM）★核心
**分段概率**（`p` 为每 tick 概率）：

| 温度区间 | 公式 / 概率 | 说明 |
|---|---|---|
| $T < 60$°C | $p = 0$ | 不蒸发 |
| $60 \le T < 100$°C | $p = 0.0003\,(T-60)$，**仅当该格有 `AIR` 邻格（表面水）** | 缓慢表面蒸发：80°C→0.006，99°C→0.0117 |
| $T \ge 100$°C | $p = \min\bigl(0.50,\ 0.02 + 0.001\,(T-100)\bigr)$ | 沸腾，温度越高越快 |

**沸腾段数值表**：

| T (°C) | 100 | 120 | 150 | 200 | 300 | 400 | 500 | ≥600 |
|---|---|---|---|---|---|---|---|---|
| $p$/tick | 0.020 | 0.040 | 0.070 | 0.120 | 0.220 | 0.320 | 0.420 | 0.500 |
| 平均 tick | 50 | 25 | ~14 | ~8 | ~4.5 | ~3.1 | ~2.4 | 2 |
| 平均秒 | 0.83 | 0.42 | 0.24 | 0.14 | 0.076 | 0.052 | 0.040 | 0.033 |

**曲线形状说明**：$T<100$ 段近似为 0（仅在表面有微量蒸发），$T=100$ 处阶跃到 0.02，随后**线性增长**、在 $T\approx600$ 处封顶 0.5（每 tick 至少熬 2 tick 才蒸发）。即：**临界温度附近「犹豫」约 0.8 秒，温度越高驱逐越暴力**。该形状服务于支柱 1（玩家能学会「水要烧到 100°C 才开」），同时高温下足够迅猛。

### 7.2 蒸汽 → 水（STEAM → WATER，冷凝）
$$p_{cond}(T) = \operatorname{clamp}\bigl(0.00015\,(100 - T),\ 0,\ 0.02\bigr),\quad T < 100$$

| T (°C) | ≥100 | 90 | 60 | 20 |
|---|---|---|---|---|
| $p$/tick | 0 | 0.0015 | 0.006 | 0.012（封顶区） |
| 平均秒 | ∞ | 11.1 s | 2.8 s | 1.4 s |

**形状**：越冷越快冷凝；室温蒸汽约 1.4 s 变回水（形成「雨」），热蒸汽在热源附近可长时间存留。$T\ge100$ 恒不冷凝。

> **v1.1.0 修订（消亡条件）**：蒸汽曾有一条 `lifetime = 600` 的**强制寿命**——到期后**无论温度**一律转 `WATER`，这会在 300 °C 时也凭空冷凝，**违反本节「$T\ge100$ 恒不冷凝」**。现**已删除**该寿命（`STEAM.lifetime = -1`）：蒸汽的唯一消亡路径是**本节的冷凝（仅 $T<100$）**与**顶部逸出（§13.3）**。安全性：蒸汽由沸腾/岩浆淬水按有限速率产生，且顶部会逸出，不会无界累积；被密封的超热蒸汽长期存留是**物理正确**的。

### 7.3 冰 ↔ 水（ICE ↔ WATER）
- **融化** ICE → WATER（$T \ge 0$）：$p = \operatorname{clamp}\bigl(0.05 + 0.005\,T,\ 0,\ 0.50\bigr)$
  | T | 0 | 10 | 20 | 50 | ≥90 |
  |---|---|---|---|---|---|
  | p | 0.05 | 0.10 | 0.15 | 0.30 | 0.50 |
- **凝固** WATER → ICE（$T \le -2$）：$p = \operatorname{clamp}\bigl(0.025\,(-T),\ 0,\ 0.40\bigr)$
  | T | -2 | -5 | -10 | -16 | ≤-16 |
  |---|---|---|---|---|---|
  | p | 0.05 | 0.125 | 0.25 | 0.40 | 0.40（封顶） |
- **迟滞（hysteresis）**：凝固阈值 $-2$ 与融化阈值 $0$ 之间形成 $[-2,0]$ 的**死区**，防止在 0°C 附近来回闪烁。

### 7.4 雪 → 水（SNOW → WATER，$T \ge 0$）
$p = \operatorname{clamp}\bigl(0.08 + 0.005\,T,\ 0,\ 0.50\bigr)$：0°C→0.08，20°C→0.18，≥84°C→0.50。雪比冰融得更快（结构疏松，近似）。

### 7.5 岩浆 → 石头（LAVA → STONE，$T \le 700$）
$p = \operatorname{clamp}\bigl(0.01\,(700 - T),\ 0.02,\ 0.50\bigr)$：700°C→0.02（缓慢，平均 50 tick），690°C→0.10，≤650°C→0.50。
**迟滞**：岩浆凝固于 700°C，而石头熔于 1200°C（§7.6），$[700,1200]$ 为死区，避免岩浆/石头抖动。

### 7.6 石头 → 岩浆（STONE → LAVA，$T \ge 1200$）
$p = \operatorname{clamp}\bigl(0.005\,(T-1200),\ 0,\ 0.30\bigr)$：1200°C→0，1300°C→0.30（封顶）。需要持续高温。

### 7.7 其他熔融（近似：统一熔为 LAVA）
| 元素 | 阈值 | $p$ | 说明 |
|---|---|---|---|
| GLASS → LAVA | $T \ge 1400$ | 0.02 | 玻璃熔融（近似归入岩浆） |
| METAL → LAVA | $T \ge 1500$ | 0.02 | 金属熔融（近似） |
| SALT → LAVA | $T \ge 801$ | 0.02 | 盐熔融（近似） |
| SAND → GLASS | $T \ge 1100$ | 0.03 | 沙烧结成玻璃（炼玻璃链；**v1.1.0 由 1700 降至 1100**） |

> **近似说明**：元素集只有一个「熔融态」（LAVA），故所有熔融统一映射为 LAVA；这是元素数量限制下的设计决策，物理上不精确但规则清晰。
>
> **SAND → GLASS 阈值近似（v1.1.0，`SAND.GLASS_T` 1700 → 1100）**：真实石英熔点 **1713 °C**、钠钙玻璃软化约 **600–800 °C**。本作取 **1100 °C**，是为了在「最高热源岩浆 1200 °C + 对称导热（格温不超热源）」的约束下，留出约 **100 °C** 的可用反应窗口。**近似**。
> - **物理边界（保留，有价值）**：导热为**对称温度交换**（守恒 $\Sigma T$），故**任何格子的温度都不可能超过其热源**——1200 °C 岩浆最多把被其**吞没**的沙加热到 **≈1198.8 °C**（实测 320×180 整池岩浆，峰值 1198.82 °C）。取 1100 即在此天花板下留出 ≈99 °C 窗口。
> - **几何边界（重要）**：沙（密度 1600）**浮于**岩浆（2800）之上，故「把岩浆倒在沙上」会让沙升到岩浆表面，只能**单面受热**（实测峰值仅 ≈528 °C，**不足以成玻璃**，且与岩浆体积无关）。要炼玻璃，沙必须被岩浆**吞没（多面受热）**——即「先在容器/池中灌入大片岩浆，再在其中画入沙块」，见 §13.2 与 `tests/run.js` 第 15 项。

### 7.8 液氮 → 空气（LN2 → AIR，$T \ge -196$）★v1.1.0 修订
$p = \operatorname{clamp}\bigl(0.0005\,(T+196),\ 0,\ 0.50\bigr)$：−196 °C → **0**（刚画下不蒸发），−150 °C→0.023，−100 °C→0.048，0 °C→0.098。
> **修正理由（审查 F09）**：首版为 `0.03 + 0.002(T+196)`，在 −196 °C 就已经有 $p=0.03$，
> **液氮一画到画布上 0.55 秒就全部汽化**，玩家根本来不及看到它冻结周围。
> 改为纯斜率式后，液氮必须先被环境加热才会汽化，实际寿命由 §6.3 的弛豫主导（约 7 s 升到 −100 °C）。
- **冷效应**：LN2 存在时其低温经导热（k=0.35）迅速抽走邻格热量（§6）。
- **产物 = `AIR`（v1.1.0 修订，原为 `STEAM`）**：氮气**回归大气**最自然，且**修复「凭空造水」守恒漏洞**——原实现 LN2 → `STEAM`，蒸汽随后经 §7.2 冷凝成 `WATER`，导致「倒一片液氮凭空造水」（实测 WATER $0 \to 148$ 格）。改为 `AIR` 后汽化产物即大气本体（原格温度随之保留，形成一圈低温空气），**WATER 计数不再增加**。
  > 该「备选方案（Backlog）：LN2 → AIR」现**已采纳为主方案**，见 `docs/adr/0005` 修订记录。元素集仍无独立氮气，故以 `AIR` 代表「氮气/大气」。

## 9. 燃烧模型（Combustion Model）

### 9.1 点火三要素
一格燃料 $F$ 被点燃需**同时**满足：

1. **可燃**：`flammability > 0`；
2. **邻近火源**：4 邻域存在 `FIRE` 或 `LAVA`；
3. **有氧 / 通气**：满足 `oxygen(F)=true`，即 **Chebyshev 半径 2 内存在 `AIR`（仅 `AIR` 算氧）**。`GAS/STEAM/SMOKE` 不算氧。
   （实现细节：氧搜索**不可穿透 `WALL`**——否则 1 格厚的密闭盒会被半径 2 判据「看穿」到盒外大气，使密封盒持续燃烧。修订自旧「4 邻接 `AIR/GAS/STEAM`」，见 `COMBUSTION-MODEL.md §3.1` / ADR-0006。）

满足三条后，按 §9.2 的概率判定是否点燃。
**特例（自燃阈值）**：若该格自身温度 $T \ge$ `ignitionTemp`，则 $p_{ign} = 1.0$（已被烤到燃点，必燃）。

> 这样两个属性各有确定语义：`flammability` = **接触火焰时的引燃速度**；`ignitionTemp` = **自燃阈值**。
> 首版把"自温 ≥ ignitionTemp"混进条件 1，导致一张表里同时存在"必燃"与"按概率"两条互相冲突的路径（审查 F05），现已拆清。

### 9.2 点燃概率与火焰寿命
$$p_{ign}=\texttt{FuelSpreadP}[F]\times b_{dir},\quad b_{dir}=\{上1.5/平1.0/下0.6\}$$
- **固/粉/液燃料**点燃后 `element=FIRE`、`latent=燃料id`、`age=0`；**该火焰被"锚定"**（不上升、不受风，`movement` 跳过），寿命 = `FUEL[latent].burnTicks`（见 `COMBUSTION-MODEL.md §6.1`），**不使用 `LIFE_BASE`**。
- **自由火焰**（`latent==0`，来自瓦斯/火药/爆炸/手绘）：寿命 = `FIRE.LIFE_BASE ± jitter`，会上升、受风。
- 燃尽后：锚定火焰按 `CHANNEL_P` 判 AIR/ASH（缺氧窒息而亡则一律 ASH，不再造氧）；自由火焰按 `SMOKE_P` 判 SMOKE/AIR（缺氧窒熄则留 SMOKE）。
- **锚定的作用**：燃料火焰留在原位，烧尽后开出的 AIR 通道使其成为下一层燃料的相邻火源 → 火焰前沿得以逐层深入（N1 修复的核心，见 `COMBUSTION-MODEL.md §1` / ADR-0006）。

### 9.3 燃料残余（**已实现**：`ignite()` 把燃料 id 存入 `latent`，`agePass` 据 `FUEL.channelP` 判通道/灰）
> 燃尽后按 `CHANNEL_P` **开 `AIR` 通道**（让火焰前沿深入），否则留 `ASH`。**相对旧表下调 ASH 比例**——保证 AIR 通道是 N1 修复的必要条件。

| 燃料 / 自由火焰 | 开通道 `AIR` | 残渣 `ASH`／`SMOKE` |
|---|---|---|
| WOOD | 0.50 | 0.50 (ASH) |
| COAL | 0.20 | 0.80 (ASH) |
| OIL | 1.00 | 0.00 |
| PLANT | 0.70 | 0.30 (ASH) |
| DUST | 0.80 | 0.20 (ASH) |
| SEED | 0.70 | 0.30 (ASH) |
| VIRUS | 0.80 | 0.20 (ASH) |
| GUNPOWDER | 0.50 | 0.50 (SMOKE) |
| 自由火焰（`latent==0`，通气） | 0.50 | 0.50 (SMOKE) |
| 缺氧窒息而亡（任意火焰） | 0.00 | 全部 ASH/SMOKE（**不再造氧**） |

### 9.4 快燃 / 爆燃（GUNPOWDER、GAS）
- 点燃后**不表现为持续火焰**，而是「本格→FIRE」并立刻以 $p=0.8$ 向 8 邻域的其它同类 `GUNPOWDER`/`GAS` 传播点火（链式），造成快速蔓延火光——**近似爆炸的观感**，但仍是格级传播（非瞬时）。

### 9.5 爆炸（TNT）
- **触发**：TNT 格遇 `T>=180`、邻接 `FIRE`、或被另一次爆炸波及（`flags` 传播）。
- **半径**：$R_{TNT} = 6$ 格（切比雪夫距离）。
- **效果**：对半径内所有格——
  - 静态固体（除 WALL）：$p=1.0$ → `AIR` 或 `FIRE`（$p=0.5$ 各半）；WALL 免疫；
  - 可移动物质：$p=0.6$ → `FIRE`，$p=0.4$ → 被抛出（沿径向移动 1–3 格，近似冲量）；
  - 温度：半径内所有格 $+400$（钳制到 `MAX_TEMP`）；
  - 引爆半径内的其它 TNT/GUNPOWDER/GAS（链式，最多 `MAX_CHAIN = 8` 层）。
- **性能上限**：单 tick 爆炸处理格数上限 `MAX_EXPLOSION_CELLS = 2000`，超出则截断。

### 9.6 耗氧与维持（Oxygen Consumption）★**行为变更**（docs/PHYSICS-AIR.md §8.2 / `COMBUSTION-MODEL.md §4`）
- **点火需通气**（§9.1 条件 3）。点燃时即扣掉该格**可达氧**的 1 格 `AIR` → `SMOKE`（`consumeOxygenNear`，半径 2 内、不穿墙）——点火所依赖的氧被真实扣除。
- **持续耗氧**：每个"锚定火焰"每 `OXY_CONSUME_INTERVAL=30` tick，用确定性哈希选 1 个**邻接** `AIR` → `SMOKE`（尾气 100 °C）。
- **不通气加速熄灭**：锚定火焰不通气时 `age` 每 tick 额外 +`SMOTHER_EXTRA=3`（寿命缩至标称的 1/4）。
- **封闭硬条件（H-SEAL）**：封闭区内 `AIR` 计数 = 0 ⇒ 无火可点燃/维持 ⇒ 必然自熄。**关键**：缺氧窒息而亡的火焰一律留 `ASH`/`SMOKE`、**绝不再造 `AIR`**，否则 AIR 归零后会被反复「复活」而破坏自熄（见 ADR-0006）。
- **净氧账本**：每燃尽 1 格燃料 `ΔAIR = CHANNEL_P − ⌈burnTicks/OXY_CONSUME_INTERVAL⌉`，**所有燃料均 < 0**（`COMBUSTION-MODEL.md §4.3`）→ 封闭系统 Air 单调下降 → 燃烧必然终止。
- **守恒**：`AIR → SMOKE` 仍是"物质格数 +1"的唯一合法路径（§13.1）。

## 10. 生命 / 植物模型（Life & Plant Model）

> **本节（§10）已由 `docs/PLANT-MODEL.md`（严格生态植物模型）整节替换。** 以下为摘要；规则细节与全部验收项以 `PLANT-MODEL.md` 为准。

### 10.1 种子发芽（SEED → PLANT）★核心问题 ③（严格生态：**四条件**）
每 tick 对每个 `SEED` 格评估**四条件**（必须同时满足，满足累积、否则衰减）：

| 条件 | 判据 | 阈值 |
|---|---|---|
| **① 着地 ground**（新增，严格生态核心） | 正下方一格 `(x, y+1)` 为"地面"（`state` 为 solid/powder 的元素，或底行 $y=H-1$） | `SEED.GROUND_REQUIRED = true` |
| **② 湿度 moisture** | Moore 邻域（半径 `SEED.MOIST_RADIUS = 2`）内存在 `WATER`，**或**含水量 > 0 的 `SOIL`（湿土） | $\ge 1$ |
| **③ 温度 temp** | 该格温度 | $5 \le T \le 40$°C |
| **④ 暴露 exposure**（「光」的近似） | 正上方连续 2 格中至少一格是 `AIR` 或 `WATER` | 未被深埋 |

- **计时器**：四条件全满足时 `age++`；任一不满足时 `age = max(0, age - 2)`（衰减）。
- **发芽判定**：当 `age >= SEED.GERM_TIMER_REQ = 90`（连续满足 $\ge 1.5\ \text{s}$）后，每 tick 以 $p_{germ} = 0.05$ 判定 → `SEED → PLANT`（平均再等 20 tick ≈ 0.33 s）。
- **极端温度**：$T > 60$ → 种子直接死亡（→ `ASH`，$p=0.5$ / `AIR`）；$T < -10$ → 死亡（→ `AIR`）。
- **浮空种子**：因条件 ① 不满足，`age` 持续衰减到 0，**永不发芽**（修复缺陷 B4 的第一道闸）。
- **`SOIL.age` 语义**：不再是"寿命"，而是**含水量 moisture**（0–`SOIL.MOISTURE_MAX=200`）：邻接 `WATER` 时 `+SOIL.MOISTURE_GAIN`、无水时 `-SOIL.DRY_RATE`。旧规则把"干土"也算湿度来源（审查 F08），新规则要求 `age > 0` 才算湿土。

> **关于「光」**：MVP **无光模型**，用「暴露度（上方有空气/水）」作为光的近似（设计决策，见 `DESIGN.md` R10）。

### 10.2 植物生长（严格生态：**须连地 + 耗水 + 供水封顶 + 整株枯死**）
- **连地判定 `isRooted`**（新增，修复 B4）：生长前用**有界 BFS**（上限 `ROOT_SEARCH_MAX = 128` 格）判定该植物格是否经 4 邻域 `PLANT` 连通到"地面"（正下方为 solid/powder，或底行）。检测每 `ROOT_CHECK_INTERVAL = 15` tick 节流一次。
- **向上生长**：**必须** `isRooted == TRUE`、（且）正上方为 `AIR` 或 `WATER`、（且）柱高 $h < \texttt{PLANT.CAPILLARY\_HEAD} = 30$、（且）根区半径 `WATER_REACH = 4` 内有 `WATER` 或湿土。满足后 $p_{grow} = \texttt{GROW\_P}\times(1 - h/\texttt{CAPILLARY\_HEAD})$ 在正上方生成 `PLANT`。**已删除写死的 `MAX_HEIGHT = 40`**——高度改由"毛细供水极限 + 可持续供水量"自然封顶（软墙，视觉自然）。
- **生长耗水**（严格生态要求 ③）：每次成功生长以 $p=\texttt{WATER\_COST\_P}=0.5$ 从根区取 1 单位水（`WATER → AIR`）；无自由水时抽湿土（`SOIL.age -= SOIL_DRAW`）。水尽 → 生长暂停（不是立即死）。
- **向水蔓延**：`SPREAD_WATER_P` 保留，但**不再把水直接变成植物**（原实现是"疯长"主因）；侧枝若不连地则 `isRooted == FALSE` → 不生长、随后枯萎。
- **整株枯死**（新增，修复 B5）：以**群落级**评估两个触发——① **断根** `isRooted == FALSE` 持续 `ROOT_LOSS_GRACE = 90` tick；② **干旱**：根区无水无湿土持续 `WILT_TICKS = 300` tick。任一触发到限 → 用**一次 BFS 收集整个群落**，在**同一 tick** 内全部变为 `DUST`（`DEATH_DUST_P`）——杜绝"顶端反复枯死下雨"（原实现逐格枯萎产生 391 格灰尘）。
- **生命上限**：单株规模 $\le \texttt{MAX\_COLONY} = 512$；PLANT 可燃（§9）与被病毒感染（R15）。
- **交互补充**：`ACID + PLANT → DUST`（S-ACID）；`LAVA + PLANT → FIRE`（S-LAVA，同 tick 不等慢热）。

### 10.3 病毒（VIRUS）
- 感染：见 R15 / R16。病毒自身不移动（`movable=false`），靠 PLANT/WOOD 结构扩散。病毒可燃（ignitionTemp 300）。被感染的植物格脱离群落 → 该处 `isRooted` 断链 → 若整株被感染则枯萎。

## 11. 气流 / 风场模型（Airflow & Wind）★核心问题 ④

### 11.1 风场定义
全局风向量 $\vec{w} = (w_x, w_y)$ 与强度 $\sigma \in [0, 1]$：

$$w_x = \sigma \cos\theta,\qquad w_y = \sigma \sin\theta$$

- $\theta$ 为风向角；$\sigma$ = 强度（玩家滑杆 `WIND.MAX_STRENGTH = 1.0`）。默认 $\vec{w} = (0,0)$（无风）。

### 11.2 平流（Advection）
每 tick 对每个 `gas` 格：以概率

$$p_{adv} = \sigma \times \texttt{windFactor}$$

沿 $(\operatorname{sign} w_x, \operatorname{sign} w_y)$ 方向尝试移动 1 格。方向按八向离散化。

- `STEAM / SMOKE / GAS` 的 `windFactor = 1.0` → 满强度风即 $p_{adv}=1.0$，随风流线飘散。
- `FIRE` 的 `windFactor = 0.5` → 火焰被吹偏（但不被直接吹灭，仍受 R1 制约）。
- 轻质粉末（`SNOW 0.4 / DUST 0.3 / ASH 0.3 / SEED 0.2`）**仅在其正下方为 `AIR` 时**（即处于空中）受风漂移。
- **空气本体也受风**（新增，§5.4-4）：风只平流"携带热量（$|\Delta|>1$ °C）"的空气格，受风敏感度 `AIR.WIND_FACTOR = 0.5`。纯室温空气不搬运（画面等价、成本可控）。

### 11.3 热对流（Convection）——**由 `airPass` 浮力取代旧近似**
- 本作已让**所有气体默认上升**（§5.3）。
- **旧近似（已取代）**：原「任一 `EMPTY` 格若 $T > 200$°C 就给正上方气体额外上升推力（$p=0.3$）」是"给别的格加推力"的假对流。现改为**空气自身的真实浮力**（§5.4）：任一 `AIR` 格若 $\Delta = T - T_{amb} > \texttt{AIR.BUOY\_DT}=40$ °C 即按温差概率自身上浮（顺带带走热量），冷空气 $\Delta < -40$ °C 下沉。`WIND.CONVECT_*` 作为兼容项保留，但不再驱动对流。

### 11.4 玩家风工具
- 在画布上拖拽定义 $\theta$（起点→终点方向）与 $\sigma$（拖拽长度归一化，或滑杆设定）。
- 八向罗盘按钮提供快捷方向；`Reset Wind` 置 $\vec{w}=0$。风一经设定即**全局持续生效**，直到下次修改。

### 11.5 风的可见性
- 画布边缘渲染淡色箭头（不遮挡内容），指示当前风向与相对强度（对齐 `ART.md` §1「界面隐形」）。

## 12. 用户四问 · 量化结论（Direct Answers）

### ① 水火关系是什么？
- **水灭火**：`FIRE` 与 `WATER` 相邻 → 火 $p=1.0$ 立即变为 `SMOKE`；同时水吸热 $+55$°C（R1）。
- **火煮水**：火的热量经导热（§6，水的比热 4186 最大、升温慢）使水升温；达到 **100°C** 后按 §7.1 概率蒸发。
- **水拦火势**：水的高比热 + 高导热 + 环境弛豫，使水成为**天然防火墙**——火焰无法穿过水体蔓延（火在 `WATER` 邻格即灭）。
- **岩浆遇水**：$p=1.0$ 岩浆变石头、水 $p=0.8$ 变蒸汽（R12）——最剧烈的「水火」交互。
- 一句话：**火在水面前必然熄灭，但会用水的升温换来一片蒸汽**。

### ② 水多久变蒸汽？与温度的关系？
见 §7.1。核心数值：
- **$<60$°C**：不蒸发。
- **$60$–$99$°C**：仅表面水微弱蒸发，$p=0.0003(T-60)$（80°C 时平均约 2.8 s）。
- **$100$°C**：$p=0.02$ → **平均 50 tick ≈ 0.83 秒**开始明显沸腾。
- **$200$°C**：$p=0.12$ → **≈0.14 秒**。
- **$500$°C+**：$p=0.42\sim0.5$ → **≈0.03–0.04 秒**（近乎瞬间汽化）。
- 关系：**温度越高，蒸发概率近似线性增长、在 600°C 附近封顶 0.5/tick**——「100°C 附近会犹豫近 1 秒，越热越快、最快每 2 tick 走一格」。

### ③ 植物发芽条件是什么？
见 §10.1。需**同时**满足四条件并累积 90 tick：
1. **着地**（新增）：正下方为地面（solid/powder）或位于底行；
2. **湿度**：半径 2 内有 `WATER`，或含水量 > 0 的湿 `SOIL`；
3. **温度**：$5 \le T \le 40$°C（$>60$ 死，$<-10$ 死）；
4. **暴露（近似「光」）**：正上方 2 格内有 `AIR` 或 `WATER`（未深埋）。
满足后连续 90 tick（1.5 s），再以 $p=0.05$ 每 tick 判定发芽。**结论：种子必须落在土/地面上，给一点水、保持室温、别埋死，约 1.8 秒后发芽；浮空种子永不发芽。**

### ④ 气流因素如何起作用？
见 §11。五个层面：
1. **全局风**：$\vec{w}=(\sigma\cos\theta, \sigma\sin\theta)$，玩家可设方向与强度 $0\!-\!1$。
2. **气体平流**：蒸汽/烟/瓦斯以 $p=\sigma \times 1.0$ 沿风移动；火以 $0.5$ 被吹偏。
3. **轻质粉末漂移**：雪/尘/灰/种子在空中（下方为 `AIR`）时按 `windFactor` 随风飘。
4. **空气本体风平流**（新增）：风搬运"携带热量"的空气格，把热量吹向下游。
5. **空气自身对流（浮力）**（新增）：热空气（$\Delta>40$°C）自身上升、冷空气下沉，形成烟囱效应（§5.4）。

## 13. 守恒与不变量（Conservation & Invariants）

### 13.1 质量守恒
- **定义**：本作「物质质量」= 非 `AIR` 的格数（每格物质质量归 1）；**总格数恒为 $W \times H = 57{,}600$**（每格始终有且仅有一个元素，空气 + 物质 = 总数，永不变化）。
- **移动守恒**：所有移动均为**交换/搬移**（A 与 B 交换，或 A→空位），格数不变。
- **相变守恒**：1 格 → 1 格（水↔汽、冰↔水、岩浆↔石），格数不变。
- **耗氧（物质 +1 路径）**：点燃时 `AIR → SMOKE`（§9.6），是物质格数 **+1** 的唯一合法路径。
- **气体逸出**：气体上升到顶边被移除并写回 `AIR`（§13.3），是**物质离开系统**的唯一合法途径；**注意空气本身不逸出**（只有"热"经顶部天空层离开，§6.3）。

### 13.2 质量创生例外（必须写明规则）
允许**创生**的元素仅两个，均受配额约束：

| 元素 | 规则 | 约束 |
|---|---|---|
| **CLONE 克隆体** | 每 `CLONE_COPY_INTERVAL = 4` tick，把 8 邻域中**一个**非静态元素复制到 `CLONE` 旁的一个 `AIR` 格 | **活体上限** `CLONE.LIVE_MAX = 5000`（世界里可移动格数达上限时暂停、降回后自动恢复）；v1.6.1 起持续复制，不再有累计配额 |
| **SPRING 水源泉** ✅**已实现** | 每 `SPRING.EMIT_INTERVAL = 6` tick，向一个相邻 `AIR` 格生成 `WATER`（20 °C） | **活体上限** `SPRING.LIVE_MAX = 6000`（**SPRING 自身喷发**累计使 `WATER` 达 `LIVE_MAX` 时暂停、降回后自动恢复；其他水源不受此闸门约束）；`SPRING` 自身不移动、不消耗 |

> 这两个是「无限资源」的**有意设计**（`DESIGN.md` 支柱 2 涌现玩法）。**v1.6.1**：改用**活体上限（live cap）**防止画面爆炸与性能崩溃 —— 旧模型的**累计配额**（产满即永久停喷）把"持续水源"退化成"一次性定量水源"（用户实测「只会给一会儿水」），已废弃。详见 `docs/SPRING-MODEL.md`。此外 §9.6 耗氧使物质可 +1（空气→烟），已在 §13.1 记账。
>
> **v1.1.0 修订**：`SPRING` 出水此前**仅在文档中**（`src/core` 无任何代码引用 `SPRING`，实测 600 tick 产水 **0 格**）。现已在 `reactions.js` 落地为反应 **R19**（见 §8 表），图鉴与守恒清单标「∞」。`src/core` 中 `SPRING` 的读取点：仅 `reactions.js`。

### 13.3 系统边界
- 气体到达 $y=0$ 再向上 → 移除（`element = AIR`，温度归环境温）。
- **空气不逸出**：顶部 `SKY_ROWS` 行的 AIR 只按 §6.3 向环境温散热，格体不删除（质量守恒）。
- 其它三边（左/右/下）为**实心墙**：粉末/液体在边缘堆积，不越界；空气亦不越界。

### 13.4 温度不变量
- 每 tick 结束钳制：$T \leftarrow \max(\texttt{MIN\_TEMP}, \min(\texttt{MAX\_TEMP}, T))$，`MIN_TEMP=-200`，`MAX_TEMP=2000`。
- ⚠️ **温度场必须用浮点存储**（`Float32Array`），**不得用 `Int16Array`**。理由见审查 F15：
  冰在空气中每 tick 只升温 0.083 °C；若存成整数 °C 并在回写时取整，这 0.083 会被**每 tick 永久丢弃**，
  冰将永不停在 −10 °C 而不融化（实测 3000 tick 毫无变化）。这正是"精度取舍必须双向验算"的典型案例。
  内存代价：320×180×4 B = 230 KB，相对可忽略。

## 15. 边界与失败模式（Boundaries & Failure Modes）

### 15.1 网格边界行为
| 边 | 行为 |
|---|---|
| 底（y = H-1） | **实心地面**：粉末/液体堆积；不可穿过 |
| 左/右（x = 0 / W-1） | **实心侧壁**：流体贴壁停止；不环绕 |
| 顶（y = 0） | **排气口**：气体继续向上即被移除（§13.3） |

### 15.2 数量上限
- 全网格最多 57,600 格；`MAX_CLONE_CELLS`/`MAX_SPRING_CELLS` 分别为 2000/1500。
- 达到配额时：克隆体/源泉**静默停摆**（不报错、不刷屏），画面保持稳定。

### 15.3 极端温度
- 全局钳制 $[-200, 2000]$°C（§13.4）。爆炸叠加的 $+400$ 会命中上限并被钳住。液氮的 $-196$ 不触及下限，仍有冷却余量。

### 15.4 多反应同时命中的优先级仲裁
同一格一帧内命合多条件时，按**固定优先级**只执行最高者（用 `flags.bit1` 落锁）：

```
1. 爆炸（TNT / 链式）            ← 最高
2. 灭火（FIRE + WATER）
3. 燃烧（点燃燃料）
4. 腐蚀（ACID）
5. 溶解（SALT + WATER）
6. 克隆 / 病毒（复制类）
7. 相变（thermalPass / phasePass）
8. 常规移动
```
理由：破坏性/剧烈事件优先，避免「一帧内先被水灭又被点燃」的矛盾态。

### 15.5 已知失败模式与对策
| 失败模式 | 症状 | 对策 |
|---|---|---|
| 液体单侧漂移 | 所有水往一边挤 | §1.4 扫描方向逐帧交替 |

### 15.6 未决 / 近似项汇总（供评审）
1. **LN2 气化映射为 `AIR`（v1.1.0 修订，原 `STEAM`）**——氮气回归大气；修复「凭空造水」守恒漏洞（§7.8）。
2. 所有熔融统一映射为 `LAVA`——**元素集限制下的近似**（§7.7）。
3. **`SAND → GLASS` 阈值 1700 → 1100（v1.1.0）**——真实石英熔点 1713 °C、钠钙玻璃软化约 600–800 °C；取 1100 是为在「最高热源岩浆 1200 °C + 对称导热（格温不超热源）」约束下留出约 100 °C 窗口。且因沙**浮于岩浆**，须**被岩浆吞没（多面受热）**方能成玻璃，单面受热峰值仅 ≈528 °C（§7.7）。
4. 「氧气」用「邻接 `AIR` 格」表示，**并在点燃时真实消耗该 `AIR`**（§9.1/§9.6）——**近似**（元素集无独立氧元素）。
5. 相变潜热用温度平台法——**近似**（§6.4）。
6. 「光」用「暴露度」近似——**近似**（§10.1）。
7. 空气自身对流由温度驱动置换近似真实流场，**不做独立气压场**（§5.4；无"抽真空→内爆"等现象）。
8. 顶部 `SKY_ROWS` 行当作"天空散热片"——**近似**（§6.3；唯一符合直觉的热出口）。
9. 空位回填空气取环境温——**近似**（避免"热空气凭空增殖"）。
10. 不做"真空"元素（30 元素与配色冻结；"无空气"用「封闭空间耗尽空气→火熄灭」表达）。

### A.3 四个最容易写错的实现点

1. **导热每对只算一次** —— 只与东、南邻居交换，否则开销翻倍（§6.1）。
2. **移动时温度必须跟着元素走** —— 只换元素不换温度，会让热沙穿过冷水后自己变凉（§13.1 移动守恒 / §5.4 `swap`）。
3. **爆炸物走引信，不走普通燃烧** —— 炸药被点燃后不能被 §9.3 的火焰规则接管，否则它会在引信期间到处乱飘（§9.5）。
4. **空气-空气导热不能跳过、空气弛豫不能过大**（B1/B2 教训）—— 原实现对"双空气对"直接 `continue` 且空气弛豫 0.10（暴露 ×2 = 0.20/tick），使空气既存不住热也传不了热（$(1-0.2)^{30}\approx0.0012$）。现用 `AIR.SELF_K` 开导热、`AIR.RELAX=0.0005` 降弛豫（§6.1/§6.3）。
