## 0. 一句话结论

**问题不在"有没有蒸汽"，在"蒸汽和石头是同一个灰度"。** 管道里跑满了 1016 格蒸汽，但渲染后蒸汽亮度 124.8、石壁 125.1 —— 差 0.3/255，5%~95% 区间重叠 **43.8%**，等于画面上不存在。

本轮只动**视觉层**（调色板 + 温度着色），不动物理、不改几何、不改引擎核心逻辑。改完：

| 判据 | 硬指标 | 改前 | 改后 |
|---|---|---|---|
| 蒸汽 vs 石头 亮度均值差（热力图视图） | ≥ 60 | **0.3** ✗ | **99.4** ✓ |
| 蒸汽 vs 石头 亮度均值差（玩家默认视图） | ≥ 60 | **13.2** ✗ | **91.2** ✓ |
| 5%~95% 亮度区间重叠率（热力图） | ≤ 10% | **43.8%** ✗ | **0.0%** ✓ |
| 5%~95% 亮度区间重叠率（默认视图） | ≤ 10% | **50.3%** ✗ | **0.0%** ✓ |
| 蒸汽 vs 背景（空气 14.7） | 不能一样暗 | 110.1 ✓ | **209.8** ✓ |

> ⚠️ **后补：§14 对用户参考图 `_ref.png` 做了复核，结论与最初的集体判断相反 —— 参考图里那条亮的蛇形带是「石壁」不是「水汽」，参考图里根本没有蒸汽。**

## 1. 问题诊断（实测数字）

### 1.1 改前的亮度分布（`node _probe_vis.js serp5 1600 legacy`）

场景 `_serp5.js` @ t=1600，320×180 网格，六条 8 格宽竖腿蛇形烟道。

**A. 热力图视图**（温度着色开 —— 这也是 `_render.js` 出证据截图的口径）

| 分类 | 格数 | min | p25 | 中位 | p75 | max | 均值 |
|---|---|---|---|---|---|---|---|
| 蒸汽 | 1016 | 94 | 125 | 125 | 125 | 141 | **124.8** |
| 石头 | 15969 | 91 | 97 | 130 | 130 | 170 | **125.1** |
| 空气 | 36856 | 15 | 15 | 15 | 15 | 15 | 14.7 |
| 水 | 3735 | 66 | 98 | 108 | 110 | 150 | 105.8 |

> 主理人实测报的是 122.1 / 125.0 / 差 2.9 / 重叠 43.8%。我这边的 legacy 模式给 124.8，差的 2.7 来自**统一橙色目标**——旧 `_render.js` 往 `(255,150,40)` 推，旧 `renderer.js` 往 `(255,176,32)` 推，我把两边统一到后者（见 §4.1）。结论完全一致。

**B. 玩家默认视图**（温度着色关 —— `main.js` 的 `showHeat: false` 默认值）

| 分类 | 均值 | 5%~95% 区间 |
|---|---|---|
| 蒸汽 | **111.4** | 89 .. 125 |
| 石头 | **124.6** | 91 .. 157 |
| 差 | **13.2**（蒸汽比石头**更暗**） | 重叠率 **50.3%** |

### 1.2 三个叠加成因

1. **基色太近，且方向错了。** `STEAM #C8D2DC / alpha 0.50` 与背景 `#0B0F17` 合成后 = `(105.5,112.5,121.5)`，亮度 **111.4**；`STONE #8A8175 / alpha 1.00` 亮度 **130.3**。蒸汽**比石头还暗 19**，这违反"水汽受光散射"的直觉。

2. **石头有三档抖动纹理，把蒸汽整个吞掉。** 石头 `dark/base/light` = 91 / 130 / 157，跨度 **91~163**。蒸汽的 111 正好落在纹理带正中 —— 不是"接近"，是"完全被包住"。

3. **温度着色不分物态，把两者往同一处推。** 旧逻辑：`T > amb+5` 时一律往橙推。蒸汽恒 ≥100 °C ⇒ 必然被推橙；而管道里的蒸汽会把石壁烤热，石壁**也**被推橙 ⇒ 色域收敛。实测 100 °C 时 `f=0.1875`，蒸汽 `(106,113,122)` → 约 `(134,120,107)`，亮度约 123，与石头 125 几乎重合。

### 1.3 一个更深的机制问题：ALPHA 在这个渲染器里不是"遮挡"

`renderer.js` 里 alpha 的唯一作用是**与纯色背景混色**：

```js
if (a >= 1) buf32[p] = pack(255, sr, sg, sb);
else        buf32[p] = pack(255, sr*a + bgR*(1-a), ...);
```

网格是**单元素/格**的 2D 阵列，格子背后没有任何东西。所以 `alpha < 1` 在近黑背景上**等于纯亮度损失**，它既不表达"半透明"也不表达"遮挡"。

这解释了为什么整个烟气类都偏暗：

| 元素 | alpha | 合成后亮度 | 症状 |
|---|---|---|---|
| STEAM | 0.50 | 111.0 | 被石头纹理带吞掉 |
| SMOKE | 0.60 | 51.4 | 与背景(14.7)只差 37，几乎看不见 |
| GAS | 0.35 | 77.1 | 被石头带完全包住 |

**这是系统性的 bug，不是蒸汽一个元素的调色失误。**

## 2. 设计原则

1. **可见性优先于"物理上的半透明感"。** 玩家看不见的元素等于不存在。在单元素/格的渲染模型里，"半透明"和"暗"是同一个旋钮，二者不可兼得 —— 取"看得见"。
2. **亮度分离 + 色相分离双保险。** 只靠亮度对色觉障碍玩家不友好；蒸汽走冷白、烤热石壁走暖橙，即使亮度接近也能分。
3. **只动视觉层。** 不改几何、不改物理、不改引擎核心循环、不加依赖。
4. **一个真值来源。** 着色逻辑不再在两个渲染器里各写一遍（详见 §4）。

### 3.2 Q1：蒸汽应该比石头亮还是暗？

**明显更亮。** 三条理由：

1. **物理直觉。** 水汽是散射介质，锅炉房/蒸汽机车里蒸汽永远是画面最亮的东西；岩石是哑光实体，吸光。旧版"蒸汽比石头暗 19"是反直觉的。
2. **画面层级不允许它待在中间。** 本场景已有的亮度阶梯是 `背景 14.7 < 水 95.3 < 石头 124.6 < 火种 143.6`。任何插在中间的值都会和某一层撞车；只有顶到最上面（>190）才是干净的。
3. **判据本身是有符号的。** V37 要求"蒸汽亮度中位 ≥ 石壁基准 + 20"，即**必须更亮**（防"把蒸汽改成纯黑也算有对比"这种反向作弊）。

## 4. 方案：温度着色分三路

### 4.1 先修"两边不一致"

改之前温度着色在两个渲染器里各写一遍，而且**三处不一致**：

| | `_render.js`（截图） | `renderer.js`（游戏内） |
|---|---|---|
| 热侧目标色 | `(255,150,40)` | `(255,176,32)` |
| 冷侧幅度 | `0.45` | `0.50` |
| 触发条件 | **总是执行** | 仅 `opts.showHeat` |

也就是说：**证据截图里看到的"蒸汽和石壁一起变橙"，玩家默认根本看不到；而玩家默认看到的"蒸汽比石头暗 13"，截图里也看不到。** 这是"截图证据"和"玩家看到的"对不上的第二个来源。

### 4.2 新增 `src/render/tint.js` —— 唯一真值来源

`_render.js`、`src/render/renderer.js`、`_probe_vis.js`、`_probe_row.js`、`_probe_smoke.js`、`tests/run.js` 全部改为调它。

**按元素的 `heatTint` 字段分三路：**

| 模式 | 热侧目标 | 热侧幅度 | 冷侧目标 | 适用 |
|---|---|---|---|---|
| `warm`（默认） | 橙 `(255,176,32)` | 0.50 | 蓝 `(30,111,184)` | 固体 / 液体 / 粉末 / 自发光气体（FIRE、LAVA 本来就是橙的，行为不变） |
| `white` | **白 `(250,252,255)`** | 0.65 | **淡蓝白 `(150,200,240)`** | 非自发光气体：**STEAM、GAS** |
| `hold` | 橙（幅度砍到 **0.18**） | 0.18 | 蓝 | **SMOKE**：受热几乎不变色 |

**Q2：为什么这样就能让"热蒸汽"和"烤热石壁"分开？**

- 热蒸汽 → 往**白**推 ⇒ 更亮（215 → 225），色相保持冷白
- 烤热石壁 → 往**橙**推 ⇒ 亮度小幅上升（125 → 130~142），色相转暖橙
- 两者在**亮度**（+100）和**色相**（冷白 vs 暖橙）两个维度上同时分离，不再收敛

冷侧同理：气体往**淡蓝白** `(150,200,240)` 推而不是深蓝 `(30,111,184)` —— 冷掉的气体不会沉进近黑背景。

**为什么 SMOKE 用 `hold`？** 真实的烟受热不会变白，变白的是水汽。让热烟保持暗灰，既物理正确，又**进一步拉开烟与蒸汽的区分度**（旧的"热烟变橙"会被误读成飞散的火星）。

## 5. Q3：要不要给气体加专门的视觉通道（辉光 / 描边）？

**不加。** 逐条否决理由见 §7。核心两条：

1. **辉光（bloom）会糊掉像素感。** 现成的 `addGlow()` 是 5×5 菱形加法柔光，半径 2 格。走廊只有 8 格宽 —— 2 格半径 = 走廊宽度的 1/4，光晕会直接溢到石壁上，把"管道结构"糊成一片渐变。这正是用户点名不要的"现代 UI 味"。
2. **亮度分离已经够了，加通道是过度设计。** 蒸汽 215 vs 石壁 125 = 1.72 倍亮度比，加上冷白/暖橙的色相差，肉眼分离毫无压力。再叠一层辉光只会降低像素锐度换不来新的可读性。

**代价对比**（估）：`addGlow` 是每格 12 次邻域加法；若只对气体开，`_diag_p2flow.js` 实测同类全屏叠加成本约 +0.15 ms/帧（≈+9%）。不是性能问题，**是观感问题**。

## 6. Q4：两边渲染器如何同步

| 环节 | 改前 | 改后 |
|---|---|---|
| 元素色 + alpha | 各自读 `Palette`（**本来就一致**） | 不变 |
| 三档抖动 | 各自调 `Palette.shadeIndex`（一致，都用 `t=0` 或 `animTime`） | 不变 |
| 温度着色 | **各写一遍，三处不一致** | **统一调 `src/render/tint.js`** |
| 环境阈值 | `_render.js` 用 `opt.ambient`；`renderer.js` 硬编码 25/15 | 统一 `Balance.PHYS.AMBIENT_T ± Tint.BAND(5)` |

浏览器侧：`index.html` 在 `renderer.js` 之前加载 `src/render/tint.js`（tint.js 在加载时读 `YS.Elements` 构造 `MODE` 表，所以必须在 `elements.js` 之后）。

Node 侧：`tint.js` 有 `module.exports`，各脚本 `require` 即可；**注意先 require `elements.js`**。

`_render.js` 新增 `opt.noTint`，可关掉温度着色以复现"玩家默认视图"。

## 8. 全局观感影响评估

**结论：没有为了迷宫这一个场景毁掉别的场景。**

1. **只改了 3 个元素**（STEAM / SMOKE / GAS），全是气体。31 种元素里 28 种逐像素完全不变，玩家已熟悉的画面不受影响。
2. **全调色板体检**：改后新增的"亮度相邻告警"为 **0**（见 §7.3）。蒸汽从"和石头/灰烬/病毒挤在一起"搬到"SAND(188) 与 ICE(203) 之间"的空档，且 SAND 是饱和黄、ICE 是淡蓝 —— 靠色相进一步分开。
3. **亮度阶梯依然单调且合理**：
   `空气 15 < 煤 41 < 油 55 < 火药 65 < 土 69 < 烟 72 < TNT 83 < 木 95 < 水 96 < 墙 99 < 灰 104 < 病毒 115 < 玻璃 120 < 植物 122 < 克隆 123 < 石头 124 < 岩浆 129 < 泉 132 < 火种 149 < 种子 151 < 强酸 153 < 瓦斯 165 < 金属 169 < 火 171 < 液氮 172 < 尘埃 172 < 沙 188 < **蒸汽 215** < 冰 203（色相区分） < 雪 231 < 盐 233`
4. **普通玩法场景（无烟道）**：蒸汽现在是一团明显发白的上升气团，跟"烧水冒白汽"的直觉一致，比原来那团跟石头同色的灰雾好读得多。烟仍是最暗的气体之一，不会喧宾夺主。
5. **风险点已在 §10 列出**，其中"蒸汽 vs 冰"是唯一需要盯的一对，且两者物态/动效完全不同。

## 9. 被否决的备选方案

| # | 方案 | 否决理由 |
|---|---|---|
| 1 | **给蒸汽加辉光 / bloom**（`addGlow` 半径 2） | 5×5 菱形加法会把 8 格宽走廊的边界糊成一圈渐变，破坏像素硬边；光晕溢到石壁上反而**丢掉管道结构**。这就是用户点名不要的"现代 UI 味"。性能不是问题，观感是问题。 |
| 2 | **把石头调暗**拉大差距 | 石头是最高频背景实体。压暗后石头(≈100)会和墙(99)、灰烬(104)、病毒(115) 挤成一团，全局观感损失远大于收益。 |
| 3 | **给气体加描边 / 轮廓线** | 需要邻域查询 + 引入新颜色；且汽柱实测只有 1~2 格宽，描边等于把汽柱整体变成线条，失去体积感。 |
| 4 | **只改温度着色、不动调色板** | 实测默认视图（无温度着色）下蒸汽 111.4 vs 石头 124.6，差 13.2、重叠 50.3%。**病根是基色太近**，改温度着色救不了默认视图。 |
| 5 | **把蒸汽改成暖白 / 米白** | 会撞 SAND(188)、SEED(151)；且米白与烤热石壁的橙同属暖色域，色相分离反而变差。 |
| 6 | **alpha 提到 1.0** | 留 0.08 的背景透出，保留一丝"不是纯实心块"的观感；也避免和 SALT/SNOW（alpha 1.0 的纯白粉末）在语义上完全同化。 |
| 7 | **蒸汽再亮到 230+** | 会撞 SNOW(231)/SALT(233)；且热力图下白推之后会顶到 240+，逼近纯白，失去冷白水汽感。 |

## 10. 遗留风险 / 已知妥协（诚实清单）

1. **V38 物理诚实性测试失败**：走廊内蒸汽最低温度 99.90 °C（要求 ≥100）。**这不是我的改动引起的** —— 本轮只动渲染层，没碰 `transitions/thermal/air`。属于工程/物理侧，需 engineering-lead 处理。（也可能与并发改动有关，需确认基线。）
2. **`alpha 0.92` ⇒ 蒸汽在近黑背景上几乎不透明。** 这是本轮最主要的妥协：在本渲染模型里"半透明"与"看得见"是同一个旋钮，我选了后者。"轻盈感"改由高明度 + 冷白 + 逐帧抖动闪动（三档跨度 182~232）表达。若将来真的要"透过蒸汽看到后面"，需要引擎支持图层化渲染，那是个独立的大工程。
3. **蒸汽(215) vs 冰(203) 差 12.2，且都是淡蓝白** —— 改后最接近的一对。缓解：冰是静态固体、蒸汽是上升气体，动效和形态完全不同。若后续仍觉得易混，建议给 ICE 实现 `elements.js` 里已声明但 renderer 未实现的 `pattern:'cross'`（十字结晶纹）。
4. **热力图下蒸汽被白推到 224.5**，与 SNOW(231)/SALT(233) 只差 7~9。缓解方案待定：把 `Tint.A_HOT.white` 从 0.65 降到 0.45（会牺牲一点"越热越亮"的表达力）。
5. **烟(72) 与 SOIL(68.5)/WOOD(96) 亮度接近**，靠"冷灰 vs 暖褐"的色相区分。可接受，但需在实际玩法里观察。
6. **`src/render/tint.js` 已成为公共契约**：`tests/run.js`（QA 侧并发修改中）与 4 个 `_probe_*.js` 都依赖它的 `Tint.BAND / Tint.MODE / Tint.apply(r,g,b,T,amb,mode)` 签名。改签名必须同步通知 quality-lead。
7. **`_look.js` 的档位注释原本错了一档**（写的 `0=. 26=: 51=- …`，实际代码是 `0=空 26=. 52=: 78=- 104== …`），已修正。**历史截图的人眼判读结论建议按新档位重读一遍。**
8. **同类缺陷（本轮未修）：`GLASS(120.2)` vs `STONE(124.4)` 只差 4.2 且都是中灰** —— 玻璃墙和石头墙在画面上几乎分不开。建议下一轮处理（方案：提高 GLASS 的 alpha 0.55 → 0.80，把它顶到 160 左右，靠"更亮 + 更青"与石头分开）。
9. **汽柱实际只有 1~2 格宽**（V37 诊断：填充率 8%~24%，平均汽柱宽度 1.0~2.1 格 / 走廊宽 8）。所以画面上是**一条细而亮的线**，不是填满走廊的粗亮带。这是物理填充率决定的，不是视觉层能改的 —— 见 §11。

# 14. 参考图 `_ref.png` 复核（重要更正）

> 起因：主理人解出参考图主色，判定"水汽 (216,216,232) 亮度 218 vs 石头 (168,184,200) 亮度 181 ⇒ 水汽必须比石头亮"，并要求把目标校准为"水汽 ≈215，石头 ≈180"。
> **我复核后认为这个归属判断是错的。** 参考图里那条亮的蛇形带是**石壁**，参考图里**没有蒸汽**。照那组数字改会原样复活本轮刚修好的 bug。以下是证据。

## 14.1 三条独立证据：亮带是石壁，不是水汽

### 证据 1 — 放大到 1 格 = 20px 看构造

见 `evidence/ref-zoom-uturn.png`（5× 放大）与 `evidence/ref-zoom-legs.png`：

- 亮带厚度只有 **2~4 格**，边缘是**严格的像素阶梯**（沿格线一刀一刀切出来的），连续数百格不抖。
- 亮带内部是**三档抖动纹理**：亮、中、暗三色像素按固定哈希散落，**和本项目 `STONE` 的 `base/light/dark` 抖动构造完全同源**。
- 气体做不到这两点：气体边界会随流动变毛、会填满走廊全宽（8 格），不会永远是 2~4 格且边缘笔直。

### 证据 2 — 亮/暗段的宽度分布（`node _ref_colors.js _ref.png`）

横向扫 7 行，量"亮段"与"间隙"的宽度（单位=格）：

```
网格行 y=40：亮段宽度 = [2.0, 4.3, 0.2, 4.3, 3.2, 4.3, 1.8, 4.3, 0.2, 2.3, 4.3, 6.8]
             亮段间距 = [10.0, 7.3, 8.6, 5.5, 10.0, 26.8, 10.4, 10.2, 20.7, 10.0, 43.4]
网格行 y=70：亮段宽度 = [0.9, 4.1, 1.4, 4.3, 0.7, 4.3, 1.6, 4.3, 0.7, 5.2, 1.4, 4.3, ...]
             亮段间距 = [8.9, 11.8, 10.7, 5.5, 8.4, 7.3, 8.9, 8.6, 7.7, ...]
```

**亮段稳定 2~4.3 格，暗段（间隙）稳定 5.5~10 格。**

- 若亮带 = 石壁 ⇒ **墙厚 2~4 格，走廊宽 8~10 格**。本项目 `_serp5.js` 的 `LEGW = 8`（走廊 8 格宽）正好对上。
- 若亮带 = 水汽 ⇒ **走廊只有 2~4 格宽，墙厚 8~10 格**。这跟"8 格宽走廊"的整体设计矛盾，也跟参考图里红色箭头跑的宽通道矛盾。

### 证据 3 — 那 23580 个亮像素是石头的**第三档抖动色**，不是水汽

参考图的亮色簇是三等份，正好对应一个材料的 `dark / base / light` 三档抖动：

| 颜色簇 | 占比 | 亮度 | 对应档位 |
|---|---|---|---|
| (108,124,140) | 3.8% | 121 | 石头 **dark** |
| (164,180,196) | 8.2% | 177 | 石头 **base** |
| (212,220,236) | 2.3% | 219 | 石头 **light** |

对照本项目 `STONE` 的三档：`#615A50/#8A8175/#A79C8C` → 91 / 130 / 157 —— **同样是三档、同样跨度约 66**。

**一个材料才会出现"三档等间距亮度簇"。气体在参考图里一格都没有。**

### 结论
参考图 `_ref.png` 是**"明亮的薄墙 + 空的暗走廊 + 手绘红箭头标注流向"的示意图**。它演示的是 **结构可读性**，不是蒸汽可见性。**它无法作为"蒸汽该多亮"的证据**（那里没有蒸汽）。

## 14.2 为什么照"水汽 215 / 石头 181"改会把 bug 复活

关键：**判据不是均值差，是区间不重叠。** 本轮 bug 的本质就是蒸汽 112 落进了石头的抖动区间 91~163 —— 均值只差 13 看着还行，区间一重叠就全糊。

按参考图的石头三档（121 / 177 / 219）：

| 方案 | 蒸汽均值 | 蒸汽 5~95% 区间 | 石头 5~95% 区间 | 重叠率 | 判定 |
|---|---|---|---|---|---|
| 参考图数字直搬 | 215 | 200..230 | 121..219 | **17%** | ✗ 超过 ≤10% 硬指标 |
| 抬到 235 | 235 | 220..250 | 121..219 | 0% | ✓ |
| 抬到 240 | 240 | 225..255 | 121..219 | 0% | ✓ |

**所以"石头 181"这个前提一旦成立，蒸汽就必须抬到 ≈240（接近纯白），而不是 215。** 主理人给的"115±15 对 180±15、差 35~40"这组数，正好落在石头抖动带内部 —— 就是 43.8% 重叠的那个现场。

## 14.3 两个方案，我推荐 A

| | **A（推荐，已落地）** | **B（不建议，需用户点头）** |
|---|---|---|
| 石头 | 不动：暖米色 `#8A8175`，亮度 **130.3**，三档 91/130/157 | 改成参考图冷蓝灰，亮度 **≈177**，三档 121/177/219 |
| 蒸汽 | 已改：`#E2EDF8` alpha 0.92，亮度 **215.3** | 必须抬到 **≈240**（近纯白） |
| 亮度差 | **+85**（远超 ≥60） | +63（刚过线） |
| 区间重叠 | **0%** | 0%（但蒸汽被逼到纯白） |
| 色相通道 | **暖石 vs 冷汽 ≈ 互补，免费且强** | 两者都是冷色 ⇒ **丢掉色相通道，只剩亮度** |
| 全局影响 | 28 种元素逐像素不变 | 石头是全项目最高频建材 ⇒ **所有用户存档画面重刷** |
| 连锁碰撞 | 无 | STONE(177) ≈ **METAL(176)** 直接撞车；还要重调 WALL/GLASS/SALT |

**推荐 A 的三条理由：**

1. **暖石 vs 冷汽是本项目最强的免费判别通道。** 石头色相 ≈35°（暖），蒸汽 ≈210°（冷），近似互补。把石头改成冷蓝灰等于**主动放弃这条通道**，然后把全部压力压到亮度上 —— 而亮度上石头自己就有 66 的抖动跨度，只能靠把蒸汽推到纯白来换空间。用一个免费通道换一个更贵的通道，不划算。
2. **参考图的"亮"是靠"薄"成立的，不是靠"亮"。** 参考图墙厚 2~4 格 ⇒ 14.3% 画面面积、细长如线。本项目 `_serp5.js` 的石头柱是 `PITCH 34 - LEGW 8 = 26 格厚`，占 27.7% 画面 —— 是一块巨大的米色板。**同一块板再提亮到 177，只会让它更压场，把蒸汽淹得更彻底。** 想接近参考图的手感，杠杆是"把墙做薄"（几何），不是"把墙做亮"（配色）。
3. **风险不对称。** A 的代价是 0，B 的代价是所有用户存档的画面重刷 + 三个新碰撞需要重调。而用户这轮的诉求是"看得见蒸汽"，不是"石头颜色不对"。

## 14.5 复核后仍成立的结论

- 蒸汽必须**比石头亮**这件事**依然成立**，但依据不是参考图，而是 §3.2 的三条理由（水汽散射直觉 / 画面亮度阶梯 / V37 有符号判据）。
- 我落地的数值（蒸汽 215、石头不动 130）不需要改。
- 参考图真正的可借鉴点，我提两条**不属于本轮、需要用户拍板**的方向：
  1. **把 demo 场景的石头柱做薄**（`PITCH` 减小 / `LEGW` 加大 ⇒ 墙 26 格 → 4~6 格）。这是最接近"如图效果"的一步，但属于几何变更，而且用户要的是"看得见蒸汽"不是"改迷宫"。**建议由主理人向用户确认。**
  2. **石头色相微调**：保持亮度 130 不变，色相从暖 35° 往中性靠（例如 `#8A8175` → `#7E8078`），让大米色板不那么像"沙丘"。**风险**：会与 `WALL #5E6874`（冷灰 102）在色相上靠近，需要同时把 WALL 拉开。收益有限，我倾向不做。
