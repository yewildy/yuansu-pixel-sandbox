- 本文只管**玩家可见的结果**：每条现象都给出「可测量或可肉眼判定」的判据。凡无法验证的形容词（"流畅""自然"）一律不写入判据。

- 风险标注：🟢 低（既有实现或直接推论）／🟡 中（需调参，有回归风险）／🔴 高（缺机制，需设计决策）。

## 2. 验收判据（Acceptance Criteria）

### 2.0 共用测量方法（instrumentation）

所有【自动】判据均用现有设施测量，不新增字段：

| 量 | 测法 | 先例 |
|---|---|---|
| 气流方向/净次数 | **逐 tick** 统计「本 tick 发生过气体置换」的格，读 `grid.flowDir` 位标（1=E 2=W 4=N 8=S；N=向上）。⚠ 渲染层只画 ≤10 tick 的新鲜位标，**测量必须逐 tick 采样**，不能看画面 | `_diag_serpent.js::countDir`、V27、V30 |
| 横向覆盖列数 | 顶部/底部横通道列宽内，出现过新鲜 E/W 位的列数 ÷ 通道列宽 | 本文新增 |
| 温度剖面 | 按行（或按区域）对 AIR 格取 `temp` 平均，输出顶→底序列 | `_diag_thermal2.js`、V25 |
| 暖层质心 | 所有 `T > 40 °C` 的 AIR 格的平均 y | 本文新增 |
| 暖层运动比例 | 暖层格中「本 tick 在移动」（`moveStamp==tick`）的占比 | `_diag_thermal2.js` B 段 |
| 水量 | WATER 格计数；水面高度 = 每列第一格 WATER 的 y | V33 |
| 冲击压 | `grid.press` 峰值与超阈值格数 | V29 |

> 注：AIR 的 `state==='gas'`，`airPass` 的每次置换都经 `swapStamp → markFlow` 写位标（附录 H.1），因此「空气的流动」与「蒸汽/烟的流动」用同一套设施测量；需要区分时（如 C3-a）按 `element===AIR` 过滤。

### 2.1 C1 闭合对流环（🟢 竖直两段 / 🔴 水平两段）

#### G0 几何前提（C1-c / C1-d 的适用条件 —— 判据的一部分，不是注）

| 项 | 要求 |
|---|---|
| 顶横通道的行区间 | ⊆ {y=1, y=2, y=3}，且**必须包含 y=1**（进入 `SKY_ROWS=2` 天空层，拿到强热沉）。推荐 **y=1..2** |
| 顶横通道上方 | **y=0 全为 AIR**（画布顶部天空层），不得是墙 |
| 两腿 | 自顶横贯通到底横（如 y=1..79） |
| 不满足时 | C1-c / C1-d 判为**「不适用」而非「失败」**，但验收报告必须写明「本次未满足 G0，水平段未测」 |

**为什么 G0 必须写进判据本身**（机制事实，不是偏好）：

1. `air.js` 顶部横向铺开的门控是 `y < TOP_SPREAD_ROWS(=4)` —— 只有画布最顶 4 行内的空气才拿到这条横向驱动（`air.js:159`，且 `airPass` 主循环自 y=1 起、y=0 不参与运动，故可用行实为 y=1..3）。
2. `pressure.js` 的静压头 `head` **在顶行恒为 0**（自顶向下累加，顶部为 0）—— 结构上不驱动顶部越过（`pressure.js:111` 原文：「顶横 head 恒 0 → 不干扰顶部机制」；§2.1.1 实测四种口径下 head 分量**恒为 0.000**）。
3. 顶横上方为墙、下方为腿内空气时，「总压最小的邻居」常被**下方**抢走 → 落入**竖直**分支 → 阈值变 `FLOW_EPS=0.5`（≈147 °C 温差）→ 横向永不触发（§2.1.1 分解表逐档列了竖直落差 vs 横向驱动）。

> **与 §4 剧本1 的关系**：G0 只是把剧本1 原文（「顶部横通道沿画布最顶两行（y=0–2）连接两腿」）从散文提升为判据。**v1.0 版把这句话放在 C1-e 的注里是本文的编辑失误**——它导致 `tests/run.js` V34 按 y=10 建几何却仍要求 ③④ 成立。见 §5 冲突 9。

**场景**（自动与肉眼共用）：墙围蛇形通道（两竖腿 + 顶部横通道 + 底部横通道，通道宽 6–10 格），顶横按 **G0** 摆在画布最顶 4 行内；底部一腿末端放热源（火种 EMBER，900 °C 或 METAL 恒温块 400 °C）。140×110 复现见 `_diag_serpent.js` / 冻结标定台 `_diag_hydro.js`。

**v1.6.3 失败基线**（600 tick 窗口，两腿均温 50.3 / 24.4 °C，差 26 °C，旧全局环境温判据）：

| 部位 | 实测 | 图中应有 |
|---|---|---|
| 左腿（热侧） | 净上升 +302388 | ✅ 上升 |
| 右腿（冷侧） | **也**净上升 +180550（下沉仅 848） | ❌ 应下沉 |
| 顶部横通道 | 横向 0 | ❌ 应横向越过 |
| 底部横通道 | 横向 0 | ❌ 应回流 |

**v1.6.6 现状基线**【R1，不满足 G0 的 y=10 几何，HEAD_K=0.000 档，600 tick 窗口】：热腿 N−S **169 796** ✅／冷腿 S−N **162 308** ✅（竖直两段已被 v1.6.4–1.6.5 修好）／顶横 E−W **0** ❌／底横 W−E **32** ❌。

**判据**（600 tick 窗口，阈值标注【初值】者待实测定标，原则：符号正确 + 有冗余余量）：

- **C1-a 热腿净上升**（🟢）：热腿区域 N 位（上）− S 位（下）≥ **+500 格次**【初值，余量 340×，几何改后须复测】，且 N ≥ 3×S。热腿内不得出现可观的 E/W 位（纯竖直）。
  > 实测【R1】：N−S = 169 796（K=0）… 173 803（K=0.1/col 口径）。示踪质心 ↑7.7~15.0 格。**本条已达成。**
- **C1-b 冷腿净下沉**（🟢，风险由 🟡 降为 🟢）：冷腿区域 S 位 − N 位 ≥ **+300 格次**【初值】。
  > 实测【R1】：S−N = 162 308 → 171 403，示踪质心 ↓13.9~18.3 格。**本条已达成**，v1.6.3 的「冷腿也上升」失败模式已消除。
  > **实现约束（判据成立的前提，沿用 v1.0）**：局部参考的**口径必须宽到能「看见」另一条腿**——行/层平均，或 ≥ 两腿间距（含中间墙，≈20–30 格）的邻域（现为 `ROW_REF_R=30`）。若参考退化为「仅与正上方/4 邻域比」，冷腿看不到热腿存在，将**原样保留 v1.6.3 的失败模式**。
- **C1-c 顶部横向越过**（🔴，**仅当满足 G0 时适用**）：顶部横通道 E 位（由左向右）− W 位 ≥ **200 格次/600 tick**【初值·未定标】，E ≥ 3×W（净方向由热腿指向冷腿），且出现过横向标记的列 ≥ 通道列宽的 60%。
  > **状态（如实）**：**满足 G0 后的取值尚未实测**。在不满足 G0 的 y=10 几何下，【R1】七档 HEAD_K × 四种 head 口径共 28 组，顶横 E−W 全部落在 **−4 ~ +4**（即恒 ≈0）；示踪质心顶横 →E 位移**恒为 0.0 格**；`T(40,12)`（冷腿顶）**恒为 20.0 °C** —— 热根本没到冷腿顶。这是【R2】V34 失败的直接证据（实得 0，门槛 >0）。
  > **依赖**：满足 G0 时，横向来自 `air.js` 的 TOP_SPREAD（`y<TOP_SPREAD_ROWS`）；不满足 G0 时只剩 `pressure.js` 的横向热压（§5 冲突 4），而后者的邻居选择会被竖直分支抢走（见 G0 理由 3）。
- **C1-d 底部回流**（🔴）：底部横通道 W 位（由右向左）− E 位 ≥ **100 格次/600 tick**【初值·未定标】，W ≥ 3×E。
  > **状态（如实）**：方向已翻正，量级远远不够。实测【R1】：32（K=0）→ **149（K=0.02，默认档）** → 174（K=0.1）→ 103（K=0.05）格次，示踪质心底横 →W 位移 1.1~5.9 格。**相对竖直两段 17 万格次差 3 个数量级**，即玩家在 `V` 气流层上基本看不到底横在动。
  > **机制归属**：驱动来自静压头 `HEAD_K`（Plan A，§5 冲突 5 已裁决）。它自顶向下累加 → 底部最强、**顶行恒 0** → 结构上只服务 C1-d、不服务 C1-c。
- **C1-e 持续性**（🟡）：第 2 个 600 tick 窗口内，四段净流量均 ≥ 第 1 个窗口的 40%（防「冲一次就停」）。
  > **v1.1 物理订正（取代 v1.0 的原注）**：v1.0 注写的「完全封在墙里 → 最终整箱均温 → 环流停止」在本模型里**不成立**，本轮订正如下。
  > - 本模型**存在分布式热沉**：空气逐格向环境温弛豫 `AIR.RELAX=0.0005`/tick（**不限于**天空层，`thermal.js:169` 行级分支仅在 `y<SKY_ROWS` 时用更强的 `SKY_RELAX`）；墙体也导热（`WALL k=0.60`）并以 `ENV_RELAX_SOLID=0.001`（暴露 ×2）弛豫。热量经「空气 → 墙 → 弛豫」持续离开。
  > - 实测【R1】：1800 tick（预热 1200 + 测量 600）后两腿温差仍有 **105.0 °C**（K=0）→ **并未均温**；竖直两段仍在 17 万格次量级活跃 → **环流并未停止**。
  > - **正确表述**（§7 采用）：若一个容器**完全没有**任何散热途径，持续加热必然使整箱趋于同一温度、温差消失、环流随之停止——这是**能量守恒的必然结果，不是 bug**。但现实世界与本模型的密封容器里，热会经壁面缓慢漏出，表现为环流**变弱**而非立刻停止。故"密封"不是顶横恒 0 的原因（§2.1.1），也不是"物理正确所以可以不做"的挡箭牌。

## 4. 验证剧本（Playtest 脚本）

> 三个手动场景，每步写清：摆放什么、等多久、应该看到什么、看不到什么算失败。均在默认 320×180 画布、60 tick/s 下进行。

### 剧本 1 · 蛇形对流环（验 C1）

1. **摆**：清屏。选「墙」（画笔 5–9）围一条蛇形通道：左腿 x≈60–100、右腿 x≈220–260，腿宽 30–40 格、高 100–120 格；**顶部横通道必须沿画布最顶两行 y=1–2（= G0）连接两腿，且 y=0 保持是空气**（y=0 是这个世界的强散热出口 `SKY_RELAX`/`SKY_VENT`，也是顶部横向铺开机制唯一生效的高度）；底部横通道在 y≈150–160 连接。懒人画法：先铺满墙，再把通道和顶部两行一起擦出来（橡皮擦 = 涂空气）。⚠ **把顶横挖在画布中间（例如 y≈10）并在其上方盖墙，则顶部越过不会生效** —— 这是机制门控，不是 bug，见 §7。
2. **摆**：左腿底部空气里放 3–5 格「火种 EMBER」。
3. **开**：按 `V` 开气流显示；设置里开热力图（可选）。
4. **等**：10–20 秒（600–1200 tick）。
5. **应该看到**：左腿淡蓝拖影持续向上 → 到顶后转为向右 → 右腿拖影向下 → 底部横通道有向左的拖影；四段合起来「转起来了」。热力图上左腿暖、右腿凉、顶部一条暖带。
6. **失败判定（任一即失败）**：右腿拖影也向上；顶部完全没有横向拖影；只转了十几秒就全停；或整条通道一个标记都没有。
7. **记录规则（v1.1 更新）**：已知当前底部回流的量级只到 149 格次（默认 HEAD_K=0.02）而竖直两段是 17 万量级（§2.1.1），因此**竖直两段 + 顶部越过正常、仅底部回流看不出来 → 不算剧本失败**，但验收报告必须写明实测格次与「横/竖」比值，并归入 §7 已知限制。
8. **反例（必须不成立）**：把顶横挖在画布中部（如 y≈10）并在其上盖墙 → 顶部越过应当**没有**拖影。若此时反而有强烈横向拖影，说明门控被破坏（回归风险：竖直热羽被抽走，A3/V24 会失败）。

### 剧本 2 · 撤源后的暖层（验 C2）

1. **摆**：清屏。用墙围一个密闭方盒（约占画布一半，壁厚 2 格），盒内是空气。
2. **摆**：盒底放一排火种（5–8 格）。开热力图。
3. **等**：15 秒（900 tick）——盒顶应已明显变暖。
4. **操作**：直接擦掉所有火种（播放态可绘制）。
5. **等**：10–25 秒，盯热力图顶部。
6. **应该看到**：擦掉后几秒内上升气流停；暖空气像「盖子」留在顶部，底边基本停在原高度（可极缓慢下移或整体变淡）；约 10–20 秒后整盒趋于一个温度（略高于 20 °C）。
7. **失败判定（任一即失败）**：撤源 10 秒后按 `V` 看，顶部仍有成片新鲜拖影持续刷新；或热力图上暖层底边持续上移；或 25 秒后顶部仍明显一坨热（旧版「25 秒不散」）。
8. **备注**：本剧本是「局部浮力判据」最直接的体感——旧版里任何高于 20 °C 的空气都会永远上升。

### 剧本 3 · 烧水气流 + 石头入水（验 C3 + C5）

1. **摆**：清屏。画一口金属锅（金属围边、锅底 1 格厚），锅内倒水（水面约 1/3 锅高）；锅底下方贴 2 格火种。在旁边空处倒一汪浅水。
2. **等**：10–20 秒到水开（见蒸汽）。
3. **应该看到（C3）**：按 `V`，锅子上方有**持续向上的新鲜拖影**（空气在被加热上升，不只是蒸汽在动）；热力图上锅上方暖区随时间向上扩展；火越大气柱越粗。
4. **操作（C5）**：选「岩石」，点进那汪水里（石头不会自由下落，「放进去」就是画进去）。
5. **应该看到（C5）**：落点水面「咚」一下，涟漪从落点向两边荡开、越传越淡，约 1–2 秒后恢复平静；肉眼看水量不变。
6. **失败判定（任一即失败）**：锅上方没有空气拖影（只有蒸汽在动）或上方空气始终室温色（「一堵墙」）；石头入水后只有落点抖一下、传不远；或入水后水面长时间不静 / 水量明显变化。

### 7.2 草稿 A — 完整说明（推荐用于用户答复 / 设置面板「关于物理」）

> **空气对流环流（当前版本的已知限制）**
>
> **已经能看到的**：热的一边往上冒，冷的一边往下沉。
>
> **还看不到 / 还很弱**：顶上横着过去、底下流回来。
> - **底部回流**：实测强度只有竖直段的**约千分之一**，按 `V` 打开气流显示，你会看到两条腿在动，但底下那条通道基本看不出在流。
> - **顶部越过**：只有在下一段的条件下才生效；摆对位置后的强度**还在复测中**，当前还没有可信结论。
>
> 我们选择把这两条如实告诉你，而不是假装环流已经整个转起来了。
>
> **想让顶部"横着过去"生效，通道要挖在画布最顶两行，并且它上方要留一条空气**——画布最顶那一行是这个世界的散热出口。把顶部通道挖在画布中间、再拿墙盖住，横向段就不会有反应；这是机制的已知门控，不是你操作错了。
>
> **关于密封容器**：如果把容器彻底封死、又没有任何散热途径，一直加热下去，整箱会趋于同一个温度，温差消失，环流也就自然停了——**这是能量守恒的必然结果，不是 bug**。本作里墙会导热、空气也会缓慢向环境温度回落，所以你实际看到的是"环流慢慢变弱"，而不是立刻停住。

### 7.3 草稿 B — 简短版（推荐用于 CHANGELOG「已知限制」条目，一行一条）

- 已知限制：闭合对流环目前只稳定兑现**竖直两段**（热腿上升 / 冷腿下沉）。**底部回流**量级仅为竖直段的约 0.1%，肉眼基本不可见。**顶部越过**要求通道位于画布最顶两行且上方留一条空气，不满足则完全无横向流；满足时的强度尚在复测。
- 已知限制：完全密封（无任何散热途径）的容器持续加热后，整箱趋于同温、环流停止——这是能量守恒的必然结果，不是缺陷。

### 7.4 草稿 C — 回答「为什么我的密封盒里看不出环流」

> 两条原因，先分清是哪一条：
> 1. **你的横向通道挖在了画布中间。** 顶部横向越过只在画布最顶几行生效；把通道移到最顶两行、上方留一条空气，顶部那段才会有反应。
> 2. **就是很弱。** 就算摆对了位置，底部回流现在也只有竖直段的约 0.1%，按 `V` 基本看不出来。这是当前实现的强度上限，不是你摆错了。
