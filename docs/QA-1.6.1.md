## 2. F1 —— 水源泉/克隆体「持续产出 + 活体上限」

### 2.1 判定：**PASS（核心行为）+ 1 条 CONCERNS（世界级上界用词不精确）**

### 2.2 证据（复现：`node _qa_f1.js`）

| 攻击项 | 实测 | 判定 |
|---|---|---|
| **A1** 预填满 6000 水（=LIVE_MAX）+ 1 泉，70 tick | `springCreated=0`（暂停）、`WATER=6000`、**产出瞬时 WATER 峰值=0**、越界 tick=**无**、累计计数单调=true | PASS |
| **A2** 排掉 300 格水后 300 tick | 恢复产出 **+46**、末态 `WATER=5746`、**产出瞬时 WATER 峰值=5746**、越界=**无** | PASS（自动恢复，非永久停喷） |
| **B** 满水后注入 80 格「60°C 冰」（非 SPRING 水源） | 融冰后 `maxWATER=6080 > 6000`，但**期间 SPRING 新增=0**（泉全程暂停） | **CONCERNS（见 §2.3）** |
| **C** 10 个 SPRING 同时喷，320×180，3000 tick | `springCreated=5000`、`maxWATER=5000`、**越界=无**、平均 **3.7 ms/tick**（机器有负载） | PASS（未灌爆、未崩） |
| **D** SPRING 被 8 面 WALL 包死，600 tick | `springCreated=0`、**0.31 ms/tick**、循环正常退出 | PASS（无死锁、无空转浪费） |
| **E** CLONE 邻接蒸汽（气体），1500 tick | `cloneCreated=3` 后停止（模板逸出 8 邻域） | PASS（行为可解释，见 §2.4） |
| **E2** CLONE 在密闭盒内 + 2 格蒸汽 | `cloneCreated=1`、盒内可移动格=3 | PASS（气体模板升到盒顶即离开邻域） |
| **E3** CLONE + 盆底**水**模板（持久），3000 tick | `cloneCreated=304`、可移动格=306 ≤5000、0.585 ms/tick | PASS（持久模板可持续产出且有界） |
| **F** 跨引擎污染探针（模块级计数器共享） | 引擎 B（空世界+1 泉）60 tick 后 `WATER=10`、`springCreated=10` | PASS（tick 回退触发强制重扫，未污染） |

### 2.3 CONCERNS：`SPRING.LIVE_MAX` 是「喷发节流」而非「世界硬上限」

- **事实**：`reactions.js` 用**低频扫描（每 30 tick）+ 产出时本地 +1** 维护 `liveWaterCount`，只在 SPRING 产出时递增。**非 SPRING 的水源**（融冰/融雪/蒸汽冷凝）**不计入**该计数器、也不重置它。
- **反验证**：预填满 6000 水使泉暂停，再注入 80 格高温冰 → 融冰后 `WATER` 达 **6080**（首越界 t=11: 6031；末 399: 6080），而**泉自身新增始终=0**。
- **结论**：任务书不变量 ②「世界里 WATER ≤ LIVE_MAX（不允许瞬时越界）」**在存在非 SPRING 水源时不成立**；但任务书不变量 ①「SPRING 持续产出、永不永久停喷」与「**SPRING 自身喷发**从不越过 6000」**成立**（A1/A2 在产出那一瞬统计，均未越界）。
- **严重度**：Minor / 文档精度问题。`docs/SPRING-MODEL.md` §2.2 的"严格上界"与 §5 的"产物总量护栏"其实已自我限定为"产物总量"；歧义在任务书的"世界级"措辞。
- **建议修法（不自行改）**：若要真正的世界硬上限，把"非 SPRING 产水"也计入（例如在 `transitions.js` 的 ICE/SNOW/STEAM→WATER 分支里 `liveWaterCount++`，或在 `refreshLiveCounts` 之外另设一个每 tick 可 O(1) 维护的全局水计数）；否则把验收标准改写为"**SPRING 喷发累计/瞬时不超过 LIVE_MAX**"。**非阻塞。**

### 2.4 观察（非缺陷）：CLONE 对「易逸出气体」几乎无效

- CLONE 需在**自身 8 邻域内**找到 movable 模板与 EMPTY 落点。气体模板（蒸汽/瓦斯）会在十几 tick 内升离邻域 → CLONE 随之 idle（E：1500 tick 仅 3 次；E2：仅 1 次）。
- 用**持久模板**（水/液体，E3）则稳定产出 304 次且有界。**属设计后果，非缺陷**，仅建议在 UI/文档提示"克隆气体效果有限"。

| **VIS-S** 无气流的静态场景 | `showFlow` 叠加像素差=**0** | PASS（静止无叠加） |

### 3.3 边缘观察（非缺陷）：气体 swap 会给液体伙伴格写入 `flowDir`

- `grid.markFlow(i,j)` 对 `i`/`j` **两格都写**。当气体上浮穿过液体时，液体现为 swap 伙伴 → 液体格被写入方向位（实测峰值 40 格）。
- **无观感影响**：`renderer.js` 的 `showFlow` 分支以 `ELS[el[p]].state !== 'gas'` 过滤，非气体格一律跳过；`addFlowNeighbor` 亦只对气体邻格提亮。故任务不变量 ③「液体/粉末移动不得写 flowDir」在"**液体自身移动**"语义下成立（F2-A=0），仅在"气体把液体当 swap 伙伴"时位标数组被写入 —— **渲染端已隔离**。若追求字节级干净，可在 `markFlow` 内加气体判据（成本极低）。**非阻塞。**

## 4. F3 —— 压强系统 `pressure.js`

### 4.1 判定：**PASS**（含 2 条"表述需精确"的说明）

### 4.2 证据（复现：`node _qa_f3.js`）

| 攻击项 | 实测 | 判定 |
|---|---|---|
| **A** METAL 盒 + 3 EMBER，4000 tick | **首格屈服（元素翻转）t=1648，坐标 (55,50)＝盒角**（角部先屈服 ✓）；`yieldStamp` 最小非零戳=1648 @(56,50)（金属蠕动到的新位）；外框 bbox **w 31→33、h 21→24**（≥2 ✓）；**对照（无热源）无屈服、bbox 不变** | PASS |
| **B** WALL 盒（同布局+热源），4000 tick | 屈服格数=**0**、WALL 100→100、bbox 31×21 不变 | PASS（IMMUNE 免疫） |
| **C** 密闭金属腔（3 EMBER）内部气压曲线 | 内部气体 maxT: 20 →(t500)882 →893… 饱和 ~890℃；maxTotalP: 1.000 →(t500)3.942 →(t4000)3.979；**非严格单调**（±0.02 抖动）；内部 `press[]` 字段全程=**0.000** | 见 §4.3 |
| **D** 爆炸冲压衰减 | Σpress s0=1047.1 → **半衰期实测=46 tick**（理论 ln2/ln(1/0.985)=**45.86**） | PASS（吻合） |
| **E** 确定性（含 TNT 冲压+联动完整场景 800 tick，两次同种子） | hash **2648134897 == 2648134897** | PASS |
| **F** 孤立 900℃ 金属块（4 邻全气体，无支撑）1000 tick | METAL 25→25 | PASS（不变形） |

### 4.3 表述需精确（非缺陷）

1. **"内部压强单调升"**：`pressurePass` 用**理想气体热压即时算**（`P = P0·(T+273)/(amb+273) + press[i]`），故内部"压强"随温度先升后**饱和**（T 被 EMBER 钉在 ~900℃，maxTotalP 稳定在 **3.94–3.98**，有 ±0.02 抖动），**并非严格单调升**。任务书若以"单调升"为验收点需改写为"先升后饱和于 ~4.0"。
2. **"打印 press 最大值曲线"**：`grid.press[]` 按设计**只存冲击压/表压**，纯加热场景恒为 **0.000**。内部压强完全来自热压（即时算、不落数组）。故对密闭加热场景应看 `temp`/`totalP`，而非 `press[]`。
