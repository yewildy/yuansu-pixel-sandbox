# ADR-0006：燃料驱动燃烧模型（锚定火焰 + 通气前沿 + 燃料驱动寿命）

- 状态：已采纳（Accepted）
- 日期：2026-10-11（v1.1.0）
- 决策人：程基岩（技术方向与主程序）
- 关联：`docs/COMBUSTION-MODEL.md`（燃烧唯一真源）· `docs/PHYSICS.md` §8/§9 · `docs/adr/0005-air-as-real-element.md` · `docs/ARCHITECTURE.md`（步进顺序）· 需求：N1（任务 #22，T6.2 实测 Major）
- 修订：`docs/PHYSICS.md` §9.1 / §9.2 / §9.3 / §9.6（其中 §9.6 为**行为变更**）

## 上下文（Context）

用户实测并复核的 **N1 缺陷**：「火焰不沿固体燃料蔓延」。基线（8×8 火置于 8×8 木块正上方，跑 1500 tick）实测 **WOOD 64 → 64，烧掉 0 格**。

根因（源码核对，三者叠加，均为 v1.0 既有缺陷、非空气改造引入）：

| # | 根因 | 位置 |
|---|---|---|
| R-1 | `FIRE.LIFE_BASE=40` 写死，与燃料无关（`WOOD.burn=120` 等燃料数值从未被使用） | `engine.js::agePass` |
| R-2 | `hasOxygen()` 用 **4 邻域且含 `GAS/STEAM`**，固体燃料内部无空气 → 内部永不着火 | `reactions.js::hasOxygen` |
| R-3 | **时序死锁**：空气通道只在火格消亡后才出现，而那时火已不在；且 `FIRE` 是气体会**浮力上升飘走** → 没有火源点燃新暴露层 | `ignite()` + `agePass` + `movement.js` |

设计侧（文策渊）产出 `docs/COMBUSTION-MODEL.md`，拍板模型；本 ADR 记录**技术决策与实现偏离**。

## 决策总览

> **燃料被点燃后变为 `FIRE`，但该火焰被"锚定"**——原地不动、不飘走（`latent>0` 即锚定）；它烧多久由**燃料种类**决定；火焰只向"通气（可达 `AIR` 半径 2）"的燃料格推进；烧尽后的残余开出 `AIR` 通道，让前沿一层层向内吃。

同时满足两个此前冲突的约束：
- **A. 火要能沿固体燃料蔓延**（N1）→ 锚定火焰 = 稳定不动的热源；前沿按 `spreadP` 逐格推进；残余开 `AIR` 通道 → 前沿持续深入。
- **B. 密封盒必须缺氧自熄**（§9.6）→ 点燃需通气 + 燃烧**持续耗氧**（净氧为负）→ 封闭系统 `AIR` 单调下降 → 必然自熄。

## 决策 1：数据表示零新增内存（复用 `element/latent/age/temp`）

- `isFuelFire(i) = (element[i]===FIRE && latent[i]>0)` —— 来自燃料的锚定火焰（寿命/残灰按燃料）。
- `isGasFire(i) = (element[i]===FIRE && latent[i]===0)` —— 瓦斯/爆炸/手绘的**自由火焰**（会飘，用 `LIFE_BASE`）。
- `latent` 存原始燃料 id（1–30）；不改 SoA 布局（对齐 `DESIGN.md §9.2` 零 GC）。

## 决策 2：锚定（解决 R-3 的关键）

`movement.js::stepCell` 的 `gas` 分支首行：
```js
if (e === ID.FIRE && grid.latent[i] > 0) return;
```
- 燃料火焰**留在原位**，烧尽转 `AIR` 通道时**仍是下一层燃料的相邻火源** → 死锁被打开。
- 自由火焰（`latent==0`）保持气态行为（上升、受风）。

## 决策 3：通气判据（修复 R-2）+ 燃料驱动寿命（修复 R-1）

- **通气**（`reactions.js::hasOxygen`）：**Chebyshev 半径 `OXY_RADIUS=2` 内存在 `AIR`，且搜索不可穿透 `WALL`**。仅 `AIR` 算氧（`GAS/STEAM/SMOKE` 均不算）。
- **寿命**（`engine.js::agePass`）：`thr = latent>0 ? FUEL[latent].burnTicks : LIFE_BASE±jitter`。`WOOD=180 / COAL=420 / OIL=90 / PLANT=45 / DUST=60 / SEED=45 / VIRUS=60`。
- **蔓延**：4 邻接目标格需通气，`p = FUEL[id].spreadP × b_dir`（上 1.5 / 平 1.0 / 下 0.6）；`T ≥ ignitionTemp` 时 `p=1.0`（但仍需通气）。
- **残灰**：`CHANNEL_P` 开 `AIR` 通道（否则 `ASH`）。

## 决策 4：持续耗氧（§9.6 **行为变更**）

- 由旧「点燃时一次性、概率 0.5」改为「**锚定火焰每 `OXY_CONSUME_INTERVAL=30` tick 必消耗 1 格邻接 `AIR` → `SMOKE`**」。
- 不通气锚定火焰 `age += SMOTHER_EXTRA=3`（寿命缩至 1/4）。
- **净氧账本** `ΔAIR = CHANNEL_P − ⌈burnTicks/30⌉ < 0`（所有燃料），故封闭系统必自熄。

## 被否决的备选

| 方案 | 蔓延 | 密封自熄 | 结论 |
|---|---|---|---|
| **(a) 邻接 `FIRE` 即点燃（无氧判据）** | ✅ | ❌ **密封盒烧穿**（原型 P2 实测 16 格烧 13 格） | ❌ 否决（违反硬红线） |
| (b) 氧源扩到 8 邻域 | ⚠️ 只多渗一层 | ✅ | ❌ 非完整修复 |
| **(c) 锚定火焰 + 通气前沿（本 ADR）** | ✅ | ✅（净氧为负） | ✅ **采用** |
| (d) 燃料"保持元素"原地烧（不改 `element`） | ✅ | ✅ | ⚪ 备选：视觉更"木在原地"，但需改渲染/移动判据，改动面大于 (c) |
| (e) 气压场驱动前沿 | ✅ | ✅ | ❌ 超预算（Backlog） |

**为何选 (c) 而非 (d)**：已合并实现已是"燃料→`FIRE` + `latent=燃料id`"，(c) 只需给 `FIRE` 加一个"锚定"判据即可复用既有残灰/寿命机制；两者物理等价，选改动小的。

## 实现级偏离（与规格 `COMBUSTION-MODEL.md` 的差异及理由）

> 按主理人指示：规格与现状冲突时**如实说明并给出替代方案**，不闷头改。以下三处为实现级必要偏离：

1. **通气搜索「不可穿透 `WALL`」**（规格 §3.1 仅定义"半径 2 内有 `AIR`"）。
   - 若允许穿墙：1 格厚的密闭盒（QA 探针几何 6×6 外盒）会被半径 2 判据**看穿到盒外大气** → 密封盒持续燃烧，红线必失。实测探针 **0/14**。
   - 替代：`findOxygen` 用限幅 BFS（8 邻接扩展、`WALL` 视为屏障）。物理上"墙挡空气"，且 `OXY_RADIUS=2` 得以保留。

2. **点火扣除"可达氧"**（规格 §9.6 仅要求点燃时以 `OXY_CONSUME_P` 概率消耗 4 邻接 `AIR`）。
   - 单格 `AIR` 足以在半径 2 内**同时**点燃整片燃料（氧未成为约束）→ 密闭盒瞬爆。实测探针同样烧穿。
   - 替代：`ignite()` 调用 `consumeOxygenNear`——扣掉目标格**可达**的 1 格 `AIR`（半径 2、不穿墙、必消耗）。氧由此成为**真实预算**：1 格 `AIR` ≈ 1 次点火。

3. **缺氧窒息而亡不再造氧**（规格 §5.1 残灰仅按 `CHANNEL_P` 判定）。
   - `CHANNEL_P` 在密闭盒里每次熄灭都重造 `AIR`，使 `AIR` 归零后被反复「复活」→ 红线不稳（多种子 86%）。
   - 替代：`agePass` 中若火格**不通气**则残灰一律 `ASH`（燃料）/`SMOKE`（自由火焰），**绝不产出 `AIR`**。物理上"完全燃烧才留通风道，窒息燃烧只剩碳渣"。次生：**纯自然自由火焰紧贴可燃固体时亦锚定**（`movement.js::adjFlammableSolid`），否则手绘火源在 1 tick 内上浮飘走、来不及点燃燃料（开放探针的失败点）。

> 上述偏离使两条探针（开放/密封）在 **10 个种子**下稳定通过；仅按规格字面实现的版本无法同时满足。

## 性能取舍（护栏）

| 手段 | 作用 |
|---|---|
| `MAX_BURN_CELLS=8000` | 同时 `FIRE` 格数上限（惰性计数，本 tick 首次蔓延判定时统计一次） |
| `findOxygen` 快速路径（8 邻接直判） | 开阔空气中绝大多数调用 O(1) 返回，避开 BFS |
| 复用既有 `reactStamp` / `fill4` | 零新增热路径分配 |

实测（Node/V8，320×180，best-of-3）：**同时 5000 格燃烧的单 tick 增量 ≈0.5–0.7 ms**（预算 ≤1.5）；含尾气累积的长窗 ≈1.5 ms。既有护栏（空画布 ≤0.3 ms、95% 填充 ≤10 ms）未退化。

## 后果（Consequences）

**正面**
- N1 修复：开放木条 1200 tick 消耗 **100%**；8×8 木块 ≤600 tick 消耗 **98%**；8×8 煤块 ≤1200 tick 消耗 **100%**。
- 密封盒缺氧自熄：残余木 **≥93%**、盒壁完整、火自熄（10 种子稳定）。
- 旧标定全部保留：岩浆 2.2 s 凝固（F01）、冰 −10 °C 约 2.25 s 融化（F15/9a/9b）、水 20 °C 不蒸发（7c）、空气导热 A1、热空气上升 A3、守恒不变量 #16（id ∈ [1,30]）。
- 零新增元素 / ID 映射 / 配色 / 存档版本不变。

**负面 / 代价**
- 手绘火源"贴着燃料"时会原地锚定（观感：火焰贴着木料烧而非上窜）；离开燃料后恢复上浮。这是换取"向内蔓延可靠"的代价（记为近似 N1-A4）。
- 温度/尾气账本多一份持续耗氧开销（见性能表）。
- 缺氧窒息而亡一律留 `ASH`/`SMOKE`（不复原为燃料、不产 `AIR`），是"缺氧自熄"的近似实现（N1-A1）。

**跟进 / 知识缺口**
- 真机浏览器性能需复测（Node 无法覆盖 canvas/ImageData）。
- `burnTicks` 是唯一调参旋钮；若真机体感"烧得太慢/太快"，调 `FUEL[].burnTicks`。
- 若未来做气压场（Backlog），`spreadP`/`OXY_RADIUS` 是天然扩展点。
