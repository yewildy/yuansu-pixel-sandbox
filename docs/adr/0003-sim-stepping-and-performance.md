# ADR-0003：仿真步进与性能策略

- 状态：已采纳（Accepted）
- 日期：项目 v1.0
- 决策人：程基岩（技术方向与主程序）
- 关联：`docs/PHYSICS.md` §1.2/§1.4/§6.1/§6.4/§13；`docs/DESIGN.md` §9；`docs/adr/0001`、`0002`

## 上下文（Context）

需要把 `PHYSICS.md` 的更新顺序与守恒律落成可测代码，并解决三处必须做决定的问题：

1. **步进解耦**：如何让物理与渲染帧率无关，又不因掉帧螺旋死亡？
2. **防重复移动**：§1.4 的「本帧已移动」标记用位清零还是别的？（与 ADR-0001 联动）
3. **导热守恒 vs 标定**：§6.1 的离散导热式 `T_i' = T_i + α Σ (k_i+k_j)/2 (T_j−T_i)` 与「守恒 Σ c_i·T_i」在数学上**不可兼得**——需要拍板。
4. **相变潜热平台**：§6.4 的平台法与 §7 的概率是什么关系？

## 决策 1：固定步长 + 累加器 + 子步上限

采用：`accumulator += realDt`；`while (accumulator ≥ dt && steps < MAX_SUBSTEPS) step()`；`MAX_SUBSTEPS = 4`；`realDt` 上限 0.25 s。
掉帧时**丢步**而非追帧卡死（§1.2、DESIGN §9.1）。已由无头冒烟验证：注入 0.25 s 的 `realDt` 时恰执行 4 子步并复位累加器。

## 决策 2：`stamp`（递增 tickId）取代每帧 flags 清零

`moveStamp[i] === tickId` 判「本 tick 已处理」。语义等价 §1.4，但省去每帧清零（详见 ADR-0001）。反应优先级（§15.4）用 `reactStamp` 落锁，保证一格一帧只走最高优先者。

## 决策 3：导热默认「守恒 ΣT」，比热加权守恒 ΣcT 作为可选项

**矛盾证明**：设一对相邻格 i、j，`Q = α·K·(T_j − T_i)`。
- §6.1 标定式（`ΔT_i = +Q`, `ΔT_j = −Q`）→ `ΣΔT = 0`（守恒 **ΣT**），但 `Σ c·ΔT = Q(c_i − c_j) ≠ 0`（一般不守恒 ΣcT）。
- 守恒 ΣcT 需 `ΔT_i = Q/c_i`, `ΔT_j = −Q/c_j`，但这会把「岩浆加热水 ≈ +2.1°C/tick」的标定值缩小 `c` 倍（水 c=4186 → 变 ≈ +0.0005°C/tick），**F01 修正后的关键手感将全部消失**。

二者不可兼得。决策：

- **生产模式（默认）**：采用 §6.1 标定式（对称交换，守恒 ΣT）。理由：审查 F01（α=0.005 / 空气 k=0.002）是**致命级**修正，其全部标定表（岩浆散热 2.2s、淬水 0.65s、液氮寿命等）都建立在「ΔT = Q」之上；牺牲它等于废掉岩浆/冰/液氮/火的核心玩法。
- **校验模式**：`Thermal.diffuse(grid, {energyWeighted:true})` 提供守恒 ΣcT 的实现，供单元测试严格验证「无能量创生/消灭」。
- 单元测试**两条都跑**：`ΣT`（生产模式）与 `ΣcT`（比热加权模式），相对误差均 < 1e-6。

> `specificHeat` 仍保留在其唯一被 §3 明确的用途——**弛豫加权**（§6.3 的 `r_c` 按类别取值）与未来扩展；它不进入 §6.1 的导热主线，忠于 §3 的字段定义。

## 决策 4：相变 = 两道串联闸（能量闸 + 随机闸）

严格按 §6.4/§7 实现：每 tick 对候选格
```
① 能量闸：处于阈值窗口(|T−T_pc|≤2) → 钳温到 T_pc 且 latent++；
          越过阈值但不在窗口 → latent++（不钳温、不吸潜热）；
          退回阈值另一侧 → latent−−（下限 0）；
② 随机闸：rnd() < p(T)（§7 分段概率）；
① 且 ② 同时通过 → 切换物态，latent 归零。
```
- 水 100°C 沸腾用 `LATENT_TICKS_BOIL=8`；冰融 `12`、冷凝 `6`、岩浆凝固 `10`、雪融 `4`、液氮气化 `6`。
- `WATER→ICE` 未在 §6.4 表中，复用 `LATENT_TICKS_ICE`（12）作为平台时长（记为近似）。
- 表面蒸发（60–99°C，`0.0003(T−60)`，仅表面）**不设平台闸**（§7.1 的独立路径）。

## 后果（Consequences）

**正面**
- 物理与帧率解耦；掉帧丢步不卡死。
- 更新顺序、优先级、守恒律均为确定性，可单测（17 项测试全绿）。
- 导热手感忠实 §6.1 标定；同时保有严格的能量守恒校验能力。

**负面 / 代价**
- 生产模式**不严格守恒 ΣcT**：以「比热不进导热主线」换取可玩性；这是**有意偏离**，已显式记录，待主理人/用户知晓。
- 气体风平流并入 `movePass`、`windPass` 只做粉末漂移与对流（顺序微调，服从 §5.3 优先级）。
- `latent` 用 `Uint8Array`，上限 255（远超各平台阈值，安全）。

**跟进**
- 若用户认为「严格能量守恒」优先于「岩浆手感」，切换默认 `ENERGY_WEIGHTED_CONDUCTION = true`（一行开关，`balance.js` 已预留），并同步下调相关标定表。
