### 1.2 为什么把 `density` 设为 1.2 却不会改变任何既有位移行为

现实现的四类"可进入"判定均在**第一行**对目标 id 做短路：

```js
function enterableDown(selfDens, target) { if (target === 1) return true; /* … */ }
function enterableUp  (selfDens, target) { if (target === 1) return true; /* … */ }
function enterableGas (selfDens, target) { if (target === 1) return true; /* … */ }
function enterableSide(selfDens, target) { if (target === 1) return true; /* … */ }
```

即：**任何元素都能进入/穿过空气格**，空气的 `density` 数值不参与该分支。于是：

- 粉末/液体照常下落、穿过空气 ✓
- 气体（蒸汽/烟/火/瓦斯）照常上浮 ✓
- 把空气 `density` 从 `0` 提到 `1.2` **不改变任何一条既有位移结果**（因为它走的是 `target===1` 短路，不是 `density` 比较）。

既然 `movable=false`，通用 `stepCell()` 的 `if (!E.movable) return;` 会让空气**永不**进入粉末/液体/气体任一分支 → 通用移动零成本、零行为变化。

> **结论**：空气的"能动性"完全由 §6 的 `airPass` 提供，与通用移动通道**解耦**。这是既能"真实建模"又能"不拖垮性能"的关键设计。

## 2. 真空（Vacuum）——**不保留**（设计决策）

**决策：MVP 不引入"真空"元素，也不引入独立真空态。** 理由：

1. **元素数量与配色冻结**：用户明确要求"不新增元素，30 种与 `ART.md` 配色全部不变"。真空若要可见，就必须有第 31 种颜色，直接违反约束。
2. **真空 = "无介质"**，而本作的"无介质"就是空气。若把真空做成"空气被抽走后的空位"，该空位在数据结构上与空气**无法区分**（都是"没有物质"，只有空气是"有物质的气体"）——除非引入第二个字段（气压/稀薄度），成本与收益不匹配。
3. **本作不模拟气压场**（见 §7），因此真空没有可表达"力"的载体（吸力/内爆都需要压力梯度）。

**替代与用途映射（用现有元素表达"真空的观感"）**：

| 玩家想要的"真空/无空气"效果 | 本作用的表达 |
|---|---|
| "这里没有空气，火会灭" | **封闭空间被火/烟填满后 `hasOxygen` 变假 → 火自行熄灭**（§8）。观感等价，且自然涌现 |
| "抽走空气形成吸力" | 不做（无气压场）。列入 Backlog：`VACUUM` 元素 + 粗网格气压场 |
| "太空/真空环境" | 不做。`docs/DESIGN.md` 无太空场景 |

> **标注**：`§15.6` 近似项 #3「氧气用『存在 EMPTY 邻格』近似」将改写为「**用『邻接 AIR 格』近似，并在点火时真实消耗该 AIR**」——见 §8。

### 3.2 守恒语义变更（重要）

`PHYSICS.md §13.1` 原写「质量 = 非 `EMPTY` 格数」。现改为：

> **质量（物质） = 非 `AIR` 格数**；空气不计入"物质"但**计入总格数**。
> - 总格数恒为 $W\times H = 57{,}600$（空气 + 物质），**永不变化**（每格始终有且仅有一个元素）。
> - 物质格数的增减只允许来自 §8 的"**耗氧**"（空气→烟，物质 +1）与既有的 CLONE/SPRING 创生/配额。

这保留了原有不变量（§13.1/§13.3）的可测性，同时让"燃烧消耗空气"成为一个**可记账**的事件。

## 4. 空气导热（Air Conduction）★缺陷 B1/B2 修复

### 4.1 模型：保留 §6.1 的显式差分，只改"配对系数"

沿用 `PHYSICS.md §6.1`：

$$T_i' = T_i + \alpha \sum_{j \in \{E,S\}} K_{ij}\,(T_j - T_i),\qquad \alpha = \texttt{PHYS.HEAT\_COUPLING} = 0.005$$

**唯一变更**：配对系数 $K_{ij}$ 采用**双轨制**（解决"空气要能横向导热"与"岩浆不许被空气秒抽干"这对矛盾）：

$$
K_{ij} =
\begin{cases}
\texttt{AIR.SELF\_K} = 0.5, & \text{两格都是 AIR（空气-空气，代表湍流混合增强）}\\[2pt]
\dfrac{k_i + k_j}{2}, & \text{其余配对（沿用 §6.1）}
\end{cases}
$$

| 配对 | 旧 $K$ | 新 $K$ | 效果 |
|---|---|---|---|
| 空气-空气 | **跳过（=0）** | **0.5** | 热量**能在空气中横向传导**（B1 修复） |
| 岩浆-空气 | $(0.30+0.002)/2=0.151$ | $(0.30+0.05)/2=0.175$ | 几乎不变 → F01 标定保留（§4.5） |
| 石头-空气 | $(0.25+0.002)/2=0.126$ | $(0.25+0.05)/2=0.150$ | 略增 → 空气贴近热石能升温（B1 修复） |
| 水-空气 | $(0.40+0.002)/2=0.201$ | $(0.40+0.05)/2=0.225$ | 略增，无害 |

**稳定性约束（复核 §6.1）**：单格单 tick 增益 $= \alpha\cdot 4\cdot K_{max} = 0.005\times4\times0.5 = 0.01 \ll 0.5$。显式差分**绝不振荡发散**。

### 4.2 性能安全阀：近平衡跳过

原实现跳过「双空气」是为了性能。新实现改为**"双空气且温差极小"才跳过**：

```
若 ei==AIR 且 ej==AIR 且 |temp[i]-temp[j]| < AIR.CONDUCT_EPS (=0.25 °C) → 跳过本对
```

- 一张**均匀室温的空画布** → 所有空气对温差 ≈ 0 → **全部跳过，成本回到 ≈ 0**（保住 §9.3「EMPTY 快速跳过」的收益）。
- 只有**存在温度梯度**的区域才付出真正的计算。成本 ∝ 「有温差的空气对数量」。

### 4.3 空气弛豫：0.10 → 0.0005（B2 修复核心）

原 `PHYS.ENV_RELAX_EMPTY = 0.10`（暴露 ×2 = **0.20/tick**）使空气成为"无限热库"，任何进入空气的热量**每 tick 被抽走 20%** —— 这正是 B2「600 °C 空气 30 tick 内被压回 21 °C」的精确来源。

| 键 | 旧值 | **新值** | 半衰期 | 说明 |
|---|---|---|---|---|
| `PHYS.ENV_RELAX_EMPTY`（= `AIR.RELAX`） | 0.10 | **0.0005** | $\ln2/0.0005 \approx 1386$ tick ≈ **23 s** | 空气不再是热库；仅作极慢的"兜底泄放"，防止长时间挂机热量无限累积 |
| 暴露加成 `EXPOSED_RELAX_MULT` | 对空气失效 | 空气恒用 0.0005（不乘 2） | — | 空气的"暴露"无物理意义；避免重复加速 |

### 4.4 顶部天空热沉（唯一热出口）

空气弛豫被压低后，热量若无处可去会**无限累积**（破坏 §13.4 的长期稳定）。因此引入**顶部开放边界**——物理上即"大气向太空辐射/对流散热"：

| 键 | 值 | 单位 | 说明 |
|---|---|---|---|
| `AIR.SKY_ROWS` | **2** | 行 | 顶部 $y < 2$ 的行为"天空层" |
| `AIR.SKY_RELAX` | **0.02** | /tick | 天空层内的 **AIR 格**按 $T \leftarrow T + 0.02(T_{amb}-T)$ 向 20 °C 散热（时间常数 50 tick ≈ 0.83 s） |

- **只有顶部的 AIR 格**受天空热沉；固体/液体在顶行不散热（顶行是"排气口"，不是"冷板"）。
- **空气质量不出系统**：天空层只带走"热"，不删除空气格（与气体逸出 §13.3 区别对待）。
- 形成**自然对流闭环**：热空气上升 → 到顶 → 被天空层冷却 → 变重下沉。这是本作"烟囱效应"的能量出口（§5.5）。

> **近似说明**：真实大气散热是 3D 辐射+多尺度对流；本作用"顶部 2 行恒温散热片"近似，理由：格级仿真无法表达辐射视角因子，而"顶部开放"是本网格唯一符合直觉的热出口（与 §13.3 气体逸出同一位置）。

### 4.5 量化验收（缺陷 B1 修复的证据）

**场景 A1（空气贴近热石必须升温）**：
在空画布（全 20 °C 空气）中，于 `(160, 150)` 放**单格 STONE 并令其 $T=1000$ °C**，其余不动。观测石头**正上方那格空气**的温度。

**解析推导**（石头在下方，空气在上）：
- 石头→空气导热：$q = \alpha\,K\,(T_{stone}-T_{air})$，$K=(0.25+0.05)/2=0.15$ → $q = 0.005\times0.15\times(1000-T_{air}) = 7.5\times10^{-4}(1000-T_{air})$。
- 空气横向导热损失（左/右/上三个 20 °C 空气邻格）：$3\times\alpha\cdot\texttt{SELF\_K}\times(T_{air}-20) = 3\times0.0025\times(T_{air}-20)$。
- 微分方程：$\dfrac{dT_{air}}{dt} = 7.5\times10^{-4}(1000-T) - 7.5\times10^{-3}(T-20)$。

| tick | 0 | 20 | 40 | 60 | 90 |
|---|---|---|---|---|---|
| 该空气格温度（°C，静置解析解） | 20.0 | 33.4 | 48.5 | **62.3** | 85.0 |

（浮力在 $T>60$ °C 即 $T_{amb}+\texttt{BUOY\_DT}$ 处接管，故约 57 tick 后该热空气开始上浮——见 §5。）

**验收判据（可自动化）**：

> **A1**：上述场景中，**在 0–90 tick 内，石头正上方空气格的峰值温度 ≥ 50 °C**（修复前恒为 ≈ 20.0 °C）。
> 更严判据：**tick=60 时该格温度 ≥ 40 °C**。
> **A1 反例（必须不通过）**：该格温度全程 $\le 20.5$ °C → 判定失败（说明空气导热仍被跳过或弛豫仍过大）。

**场景 A2（600 °C 空气团必须留存，缺陷 B2）**：
在空画布中央把 **5×5 格空气设为 600 °C**（其余 20 °C）。

## 5. 对流与浮力（Convection & Buoyancy）★缺陷 B3 修复

### 5.1 物理依据：用理想气体密度比定义"轻/重"

真实空气密度随温度下降：$\rho/\rho_0 = T_0/T$（绝对温标）。以 $T_0 = 293.15\ \text{K}$（20 °C）为基准：

| 空气温度 | 相对密度 $\rho_{eff}$（基准 = 1.0） | 行为 |
|---|---|---|
| −100 °C | 293.15/173.15 = **1.69** | 很重 → 下沉 |
| 20 °C | **1.00** | 中性（不动） |
| 100 °C | 293.15/373.15 = 0.786 | 较轻 → 上升 |
| 600 °C | 293.15/873.15 = **0.336** | 很轻 → 快速上升 |

本作**不显式算密度**（避免每格开根号/除法），而用**等价的温标阈值+线性概率**表达（见 §5.2），数值与上表单调一致。

### 5.2 驱动力与判据（"只在被驱动时才移动"）

对每个 **AIR 格**，令 $\Delta = T_{i} - T_{amb}$（相对环境温度），定义：

$$
p_{up} = \operatorname{clamp}\!\left(\frac{\Delta - \texttt{AIR.BUOY\_DT}}{\texttt{AIR.BUOY\_SCALE}},\ 0,\ \texttt{AIR.BUOY\_P\_MAX}\right)
$$
$$
p_{down} = \operatorname{clamp}\!\left(\frac{-\texttt{AIR.COLD\_DT} - \Delta}{\texttt{AIR.BUOY\_SCALE}},\ 0,\ \texttt{AIR.BUOY\_P\_MAX}\right)
$$

- **未驱动（$\Delta$ 在 $[-\texttt{COLD\_DT},\ \texttt{BUOY\_DT}]$ 内）→ $p_{up}=p_{down}=0$**：这是硬性性能判据——**均匀室温的空气永不移动**（空画布零成本）。
- 不引入随机漂移：方向仅由温度符号决定（确定性哈希只用于"是否触发本次移动"）。

### 5.3 上升/下沉速度表（换算到 cells/s）

> `AIR.PASS_INTERVAL = 2`：`airPass` **隔帧执行**（每 2 tick 一次）→ 每次概率 $p$ 折半为每 tick 位移。

| 空气温度 (°C) | $\Delta$ (°C) | $p_{up}$ /次 | 位移 (cells/tick) | **上升速度 (cells/s)** |
|---|---|---|---|---|
| 20 (中性) | 0 | 0 | 0 | **0** |
| 60 (阈值) | 40 | 0 | 0 | **0** |
| 100 | 80 | 0.16 | 0.08 | **4.8** |
| 160 | 140 | 0.40 | 0.20 | **12.0** |
| 210 | 190 | 0.60（封顶） | 0.30 | **18.0** |
| 600 | 580 | 0.60（封顶） | 0.30 | **18.0** |

下沉（冷空气）：

| 空气温度 (°C) | $p_{down}$ /次 | **下沉速度 (cells/s)** |
|---|---|---|
| −20 (阈值) | 0 | **0** |
| −60 | 0.16 | **4.8** |
| −100 | 0.32 | **9.6** |
| ≤ −270 | 0.60（封顶） | **18.0** |

**结论（可直接答用户）**：热空气**最快 18 格/秒（= 0.3 格/tick）**上升，穿过 180 格高网格约 **10 秒**；冷空气最快同速下沉。速度与温升成正比、在 $\Delta\ge190$ °C 处饱和。

### 5.4 热量如何随空气被搬走（无需额外代码）

空气的移动一律实现为 **`grid.swap(i, j)`**——它**同时交换 `element` 与 `temp`**。因此：

> **一个热空气格上浮时，它的温度指数一起上浮**。这就是"对流把热量带走"的全部实现，无需任何额外的热量搬运代码。

配套表现：热空气上浮后，**下方由冷空气下沉置换**（swap 交换），形成"热上冷下"的环流骨架，物理上即 Rayleigh–Bénard 对流的最小版本。

### 5.5 烟囱效应（Chimney Effect）的产生条件

**定义**：一条竖直"热空气柱"被两侧固体（WALL/STONE 等）夹持、顶部通向上方开放区（可直达 $y=0$ 天空层）、底部有持续热源时，形成**可持续的自持上升气流**。

**定量条件（全部满足才产生烟囱）**：

| 条件 | 阈值 | 含义 |
|---|---|---|
| ① 温差 | 柱底空气 $\Delta \ge \texttt{AIR.BUOY\_DT} = 40$ °C | 否则完全不动 |
| ② 通道 | 竖向通道宽 ≥ 1 格、高 ≥ 8 格，两侧为 `movable=false` 固体 | 侧向封闭，抑制横向泄漏 |
| ③ 顶部开放 | 通道顶端到 $y=0$ 之间**无固体遮挡** | 热空气能到天空层散热、冷空气能回流 |
| ④ 持续热源 | 底部每 tick 最少注入 $Q_{min}$ 热量，使柱底维持 ① | 否则柱内空气冷却后失去升力 |
| ⑤ 底端进风 | 通道底端至少有 **1 个侧面开口**通向外侧空气 | 提供"补风"，否则真空空腔形成、上升停止 |

**量化表现**：$\Delta = 100$ °C → 柱内空气以 **≈4.8 格/s** 上升；$\Delta = 200$ °C → **≈16.8 格/s**。一个高 120 格的烟囱，热空气穿越耗时从 25 s（弱热源）缩短到 7 s（强热源）。

### 5.6 量化验收（B3 修复的证据）

> **A3（热空气必须上升）**：5×5 的 600 °C 空气团置于网格中央。**tick=120 时，"温度 > 100 °C 的空气"的最上沿相对初始位置上升 ≥ 15 格**。（解析预期 ≈ 36 格；阈值取 15 留冗余。）

> **A4（冷空气必须下沉）**：5×5 的 −100 °C 空气团置于网格中央。**tick=120 时，其最下沿相对初始位置下沉 ≥ 10 格**。

> **A5（中性空气零成本）**：全 20 °C 空画布，`airPass` 处理的"驱动格"数 = **0**（可用计数器断言）。这是性能与"只在被驱动时才移动"的双重验收。

## 6. 空气流动机制（Air Flow）——可实现的**最低**方案

### 6.1 方案选型（面向 57,600 格）

| 方案 | 描述 | 成本 | 结论 |
|---|---|---|---|
| **(A) 温度驱动局部置换**（本文采用，MVP） | 空气只与"相邻空气格"交换；驱动力 = 竖向温差（浮力）+ 风。无全局气压。 | $O(n)$ 但**驱动格少时极廉价** | ✅ 采用 |
| (B) 粗网格气压/速度场 | 4× 降采样（80×45=3600 格）上解简化压力泊松 + 速度场 | 每次迭代 +0.5–1.5 ms，且需 2–3 次迭代收敛 | ⏸ Backlog（`ROADMAP.md` v1.2「气压场」已是既有规划） |
| (C) 全 Navier–Stokes | — | 远超预算 | ❌ 明确排除（`DESIGN.md §1.3` 非目标） |

**采用 (A) 的理由**：用户要的是"热空气上升、冷空气下沉、风能作用到空气本体"这三个**可观察**结果，而不是数值精确的流场。(A) 用**格级置换**同时给出这三者，且天然满足"只在被驱动时才移动"。

### 6.2 `airPass` 伪代码（可直接编码）

```
# 每 AIR.PASS_INTERVAL(=2) tick 执行一次；tick 为奇数时触发
airPass(grid, ctx):
  if (ctx.tick % AIR.PASS_INTERVAL) != 0 and PASS_INTERVAL > 1: return   # 隔帧降载
  amb = PHYS.AMBIENT_T
  budget = AIR.MAX_MOVE_BUDGET            # 单 tick 空气移动预算（见 §9）
  moved = 0
  # 自下而上扫描（与 §1.4 一致，避免同帧双跳）
  for y = h-1 .. 1:                       # y=0 不参与（天空层，只散热）
    for x in (逐帧交替: 偶 tick 左→右, 奇 tick 右→左):
      i = y*w + x
      if element[i] != AIR: continue
      if moveStamp[i] == tick: continue   # 本帧已被移动过
      d = temp[i] - amb
      # ---- (1) 浮力：热上升 ----
      if d > AIR.BUOY_DT:
        j = i - w                          # 正上方
        if element[j] == AIR and moveStamp[j] != tick:
          p = min(AIR.BUOY_P_MAX, (d - AIR.BUOY_DT) / AIR.BUOY_SCALE)
          if rng_hash(x, y, tick*211+1) < p:
            swap(i, j); stamp(i,j,tick); moved++; continue
        # 斜上（给出横向混合 / 补风）
        if d > AIR.BUOY_DT * 2:            # 只有较强热羽才斜上，避免抖动
          dx = rng_hash(x,y,tick*223+2) < 0.5 ? -1 : 1
          nx = x + dx
          if 0<=nx<w and element[y*w+nx-w']==AIR ... :
            if rng_hash(x,y,tick*227+3) < p*0.5: swap(...); moved++; continue
      # ---- (2) 浮力：冷下沉 ----
      elif d < -AIR.COLD_DT:
        j = i + w                          # 正下方
        if element[j] == AIR and moveStamp[j] != tick:
          p = min(AIR.BUOY_P_MAX, (-AIR.COLD_DT - d) / AIR.BUOY_SCALE)
          if rng_hash(x, y, tick*229+4) < p:
            swap(i, j); stamp(i,j,tick); moved++; continue
      # ---- (3) 风平流：只作用于"携带热量的空气"（见 §6.3） ----
      if wind.strength > 0 and abs(d) > AIR.WIND_MIN_DT:
        pw = wind.strength * AIR.WIND_FACTOR
        if rng_hash(x, y, tick*233+5) < pw*0.5:      # ×0.5 配合隔帧
          sx = sign(wind.x); nx = x + sx; ny = y + sign(wind.y)
          if inBounds and enterableAir(nx,ny) and moveStamp==0:
            swap(i, j); moved++; continue
      if moved >= budget: return           # 超出预算 → 本帧其余空气不动（降载）
```

**关键性质**：
- **只在被驱动时才移动**：`d` 落在 $[-COLD\_DT, BUOY\_DT]$ 的格子**直接跳过后两个分支**（只有一次减法+两次比较）。
- **自下而上 + moveStamp**：与 §1.4 一致，杜绝"同一格一帧移动多次/穿越"。
- **确定性**：全部用 `rng_hash(x,y,seed)`，同种子同结果（§1.5）。

### 6.3 风如何作用于空气本身（而不只是烟/汽）

现状：`windPass` 只吹**气体元素**与**空中轻质粉末**；`movePass` 的气体分支也只吹 `state==='gas'` 的**非空气**气体。空气升级为真实元素后，风必须也能**吹动空气**。

**方案（成本可控的近似）**：

> **风只平流"携带温度异常（或携带其它气体）的空气格"，不平流"纯室温空气"。**

理由：纯室温空气**不可见**（渲染为背景色），吹动它与不吹动它在**画面上完全相同**，却要付出 57,600 次 swap 的代价。而"携带热量的空气"被吹动时：

- 玩家能看到**烟柱/热浪被风吹弯**（因为烟与热空气一起走）；
- **热量被风搬运到下游**（热空气 swap 时温度跟着走，§5.4）；
- 成本 ∝ "有热量的空气格数"，通常很小。

| 键 | 值 | 说明 |
|---|---|---|
| `AIR.WIND_FACTOR` | **0.5** | 空气受风敏感度（对照：蒸汽/烟/瓦斯 = 1.0，火 = 0.5） |
| `AIR.WIND_MIN_DT` | **1.0** °C | 只有 $|\Delta|>1$ °C 的空气才被风搬运 |
| `AIR.WIND_ALL` | **false** | 可选：`true` 时全部空气随风漂移（完整但更贵；默认关闭） |

> **对用户问题的直接回答**：**风通过两种途径作用于空气**——(a) 直接把"携带热量的空气格"沿风向搬运（本 §6.3）；(b) 通过**浮力分支**，风改变了对流的方向（斜上/斜下的选择受风向影响）。合起来表现为"**热浪与烟整片被吹向下风处**"。

### 6.4 成本估算

| 场景 | 参与 `airPass` 的格数（平均） | 估算成本/次 | 摊到每 tick |
|---|---|---|---|
| 均匀室温空画布 | 0（全被 `d` 判据跳过） | ≈ 0.1 ms（仅遍历） | **≈ 0.05 ms** |
| 局部火灾（~2000 热空气格） | ~2000 | ≈ 0.15 ms | **≈ 0.08 ms** |
| 极端：半个画布高温 | ~14,400 | ≈ 0.9 ms（受 `MAX_MOVE_BUDGET` 截断） | **≈ 0.45 ms** |

## 7. 气压均衡（Pressure Equalization）——**近似**

### 7.1 机制：物体移走后空气如何填回

本作**不做独立气压场**（无 `pressure` 字段）。空位的填补通过三条既有/新增规则**自然涌现**：

| 场景 | 填补机制 | 结果 |
|---|---|---|
| 固体向下移动（落沙穿过空气） | `swap(i, j)`：固体与上方空气交换 → 固体落到下方，**空气被顶到上方** | 空位立即被空气填回，且带走了原格温度 |
| 固体被破坏（酸蚀/爆炸 → AIR） | 该格直接写 `element=AIR`、`temp=AMBIENT_T` | 立即成为 20 °C 空气 |
| 空气被燃烧消耗（AIR→SMOKE，§8） | 生成的是 `SMOKE`（比空气轻），随后**上升离开**；其周围空气由浮力/扩散补入 | 局部"变稀"被邻格空气补满 |
| 封闭腔内空气被抽走（理论） | 不存在——空气不能被"泵走"（无真空，§2） | — |

### 7.2 明确标注的近似

> **近似 P1**：本作用「**空气无处不在、无限供给、不可压缩（1 格恒占 1 格）**」近似真实气压均衡。
> **后果**：不会出现「抽真空 → 内爆」「高速气流嘶鸣」「气压推动活塞」等需要**压力梯度**的现象。
> **理由**：真实气压场需每格存 `pressure:Float32` + 每帧 Poisson 求解，代价与收益严重不匹配（`DESIGN.md` 性能预算 6 ms/tick）；且 900 组配对实验的判定不需要气压。
> **替代观感**：局部"真空"用「封闭空间耗尽空气 → 火熄灭」（§8）表达，玩家可感知，且实现为零成本。

> **近似 P2（空气"回填"的温度）**：空位回填的空气取 `AMBIENT_T`（而非邻格平均）。**近似理由**：真值应随邻近热源变化，但空位通常紧邻冷区；取环境温可避免"热空气凭空增殖"。列入 §14 近似汇总。

## 8. 燃烧耗氧改写（Combustion & Oxygen）+ 守恒账本

### 8.1 §9.1 点火三要素改写

`PHYSICS.md §9.1` 条件 3 原写「邻接 `EMPTY`/`GAS`/`STEAM` 近似氧气供给」。**改写为（配合 N1 模型，详见 `docs/COMBUSTION-MODEL.md §3`）**：

> **条件 3（有氧 / 通气）**：该燃料格满足 `oxygen(i)=∃AIR 于 Chebyshev 半径 OXY_RADIUS=2 内`。
> **即从"4 邻域存在 EMPTY/GAS/STEAM" → 改为"半径 2 内存在 AIR"**，并**移除 GAS/STEAM 充当氧源**（它们是燃料/惰气，不是氧气）。
> 语义：空气（`AIR`，id 1）是**唯一氧源**；点燃与维持燃烧都需通气。

代码对应（`reactions.js` `hasOxygen()` 需按新半径改为 Chebyshev-2 的 AIR 检测）：

```js
// 旧：4 邻域 t === 1(AIR) || t === 26(GAS) || t === 23(STEAM)
// 新：Chebyshev 半径 2 内 t === 1(AIR)     ← 仅 AIR 算氧
```

> 开放空间照常燃烧（大气处处有 AIR）；封闭空间照常缺氧熄灭（见 §8.3 与 `COMBUSTION-MODEL.md §4`）。

### 8.2 耗氧规则（→ §9.6，详见 `docs/COMBUSTION-MODEL.md`）

> **S9.6 耗氧（修订版 · 配合 N1 燃烧模型）**：氧的**判定**与**消耗**分离。
> - **判定（通气 ventilation）**：一格燃烧中的燃料必须满足 `oxygen(i)=∃AIR 于 Chebyshev 半径 OXY_RADIUS=2 内`，否则进入 smother 计时。
> - **消耗（continuous drain）**：燃烧期间每 `OXY_CONSUME_INTERVAL=30` tick，把 1 个邻接 `AIR` 格 → `SMOKE`（燃烧尾气）。
> - **温度**：被消耗的 `AIR` 格设为 `100 °C`（尾气温度，近似）。
> - **意义**：把"空气=氧气"从概念近似升级为**可计数、可证明自熄**的物理量。

> ⚠️ **与早期草案的差异**：本规格早期版本把耗氧定义为「点燃瞬间以 p=0.5 消耗 1 格 AIR」。该定义**不足以支撑 N1（火焰沿固体燃料蔓延）**，已由 `docs/COMBUSTION-MODEL.md` 取代——耗氧从"点燃一次性"改为"**燃烧期持续消耗 + 通气判据**"。以下账本按修订版计。

### 8.3 守恒账本（元素计数变化）

以「1 格 WOOD 在开放空气中被点燃 → 完全烧尽」为例（`burnTicks(WOOD)=180`，`OXY_CONSUME_INTERVAL=30`，`CHANNEL_P=0.5`）：

| 阶段 | 元素计数（物质，非 AIR） | 总格数（含 AIR） | 说明 |
|---|---|---|---|
| **T0 点燃前** | WOOD:1 | 1 | 燃料（燃烧态不改变元素，保持 WOOD） |
| **T1 燃烧中**（0–180 tick） | WOOD:1（燃烧态） | 1 | 燃料**保持自身元素**、原地燃烧；期间消耗 `180/30 = 6` 个邻接 AIR → SMOKE |
| **T2 燃尽**（tick=180） | ASH:1 或 AIR:1（`CHANNEL_P=0.5` 各半） | 1 | 残余：ASH 或开通道 AIR |
| **T3 烟衰减**（+`SMOKE.lifetime`=300 tick） | 全部 → AIR | 1 | 烟 → 空气（`decayTo: 'EMPTY'`=AIR） |
| **稳态** | AIR:1（+ 6 格被消耗后又衰回的 AIR） | 1 | **总格数守恒，物质归零** |

**账本结论（可直接写进测试断言）**：

| 断言 | 期望 |
|---|---|
| 总格数 $W\times H$ | 恒为 57,600（1 格 → 1 格，**永不变化**） |
| 燃料**燃烧态** | 元素**不变**（WOOD 仍是 WOOD），物质计数**不增加**（区别于早期草案的"燃料→FIRE, +1"） |
| 单格燃料燃尽 | 物质净变化 = 残余（ASH 或 AIR）；长期（烟衰减后）趋近 0 |
| **系统氧平衡** | 每燃尽 1 格燃料：消耗 $\lceil burnTicks/30\rceil$ 格 AIR，产出 `CHANNEL_P` 格 AIR ⇒ **净 ≈ −5.5（WOOD）< 0**（详见 `COMBUSTION-MODEL.md §4.3`） |
| 封闭罐内燃烧 | 因净氧为负 ⇒ **AIR 单调下降 ⇒ 必然自熄**（`COMBUSTION-MODEL.md §4.2` 硬条件） |

### 8.4 「CO₂ / 尾气」如何用现有元素表达

| 真实产物 | 本作表达 | 理由 |
|---|---|---|
| CO₂（完全燃烧尾气） | **SMOKE** | 复用既有"燃烧副产气体"，`lifetime=300` 后变回 AIR，形成**碳循环闭环** |
| 灰/残渣 | **ASH** | 沿用 `§9.3` 燃料残余（WOOD→ASH p=0.6 等） |
| 未燃尽烟尘 | **SMOKE** | 同上 |
| 消耗掉的氧 | AIR 格**被移除**（转为 SMOKE） | 让"缺氧熄火"可观测 |

## A2. ★ 导热模型重写：对称温度交换 → 体积热容加权

### A2.1 旧模型错在哪

v1.1 的生产路径是 ΔT_i = α·K·(T_j − T_i)，两侧等量相反，**守恒 ΣT**。
这条式子的隐含假设是 **所有格子的热容相等** —— 即「1 格空气」和「1 格岩石」吸热能力一样。
真实体积热容 `C = 比热 × 密度`：

| 元素 | C（J/(m³·K)） | 相对水 |
|---|---|---|
| 空气 | 1005 × 1.2 = **1.2e3** | 1/3480 |
| 水 | 4186 × 1000 = 4.19e6 | 1 |
| 岩石 | 840 × 2600 = 2.18e6 | 0.52 |
| 金属 | 450 × 7800 = 3.51e6 | 0.84 |

后果（实测）：1 格 1000 ℃ 岩石放进 64×64 空气场，热量被 4095 格空气**等权摊薄**，
稳态整场升温不到 0.3 ℃；**大片 1200 ℃ 岩浆**上方空气稳态也只有 **30–40 ℃**。
这正是用户所说的「空气温度不能传导」，也是「热空气升不动」的源头（温差太小，浮力不足）。

### A2.2 新模型

对每一对相邻格 (i, j)，令 `C_i`、`C_j` 为体积热容（`elements.js::volHeat`）：

```
r     = α · K · C_REF · (C_i + C_j) / (C_i · C_j)        // 松弛因子
ΔT_i  = +r · C_j/(C_i+C_j) · (T_j − T_i)
ΔT_j  = −r · C_i/(C_i+C_j) · (T_j − T_i)
```

- 恒有 `C_i·ΔT_i + C_j·ΔT_j = 0` → **严格守恒 Σ C·T**（测试 `1b`）。
- `C_REF = volHeat[WATER] = 4.186e6` → 水-水配对的速度与旧模型**完全一致**，标定无缝。
- **稳定性**：单格最多 4 个邻居，钳制 `r ≤ CONDUCT_R_MAX = 0.2` ⇒ 4 × 0.2 = 0.8 < 1，
  显式欧拉不会越过平衡点（测试 `1b-2` 用「空气/金属棋盘 + 20/1500 ℃」验证）。

### A2.3 实测改善

| 场景 | v1.1（ΣT） | v1.2.0（Σ C·T） |
|---|---|---|
| 1200 ℃ 岩浆上方 1 格空气（稳态） | 41 ℃ | **701 ℃** |
| 1 格 1000 ℃ 岩石上方空气峰值 | 38.1 ℃ | **895 ℃** |
| 同上，90 tick 后岩石自身残留 | 403 ℃（热量被凭空摊掉） | **824 ℃** |

### A2.4 静止空气必须是「热的不良导体」

改用体积热容后，若沿用 §4.1 的 `SELF_K=0.5`，空气-空气的 `r` 会被顶到 `CONDUCT_R_MAX` 上限，
等于让空气**瞬间均温**，热团 30 tick 就被摊平（验收 A2 失效）。
物理上静止空气 k≈0.026，是**隔热体**（羽绒服 / 双层玻璃原理），
空气侧的热量搬运应主要靠**对流**（`airPass` 的物质位移）而非分子导热。
故新增 `AIR.SELF_R = 0.0015`（体积热容模式下空气-空气的松弛因子），
单邻居 ΔT ≈ 0.00075·dT，时间常数约 330 tick。`SELF_K=0.5` 仅保留给旧的 ΣT 对照模式。

## A3. 浮力参数重标定（反馈①）

| 参数 | v1.1 | v1.2.0 | 理由 |
|---|---|---|---|
| `AIR.BUOY_DT` / `COLD_DT` | 40 ℃ | **1.5 ℃** | 真实空气 ΔT≈1 ℃ 即有可测浮力；旧值要热到 60 ℃ 才开始动 |
| `AIR.BUOY_SCALE` | 250 | **20** | 旧值下 ΔT=60 ℃ 时概率仅 0.08 |
| `AIR.BUOY_P_MAX` | 0.6 | **0.95** | 大温差时应接近每帧必动 |
| `AIR.PASS_INTERVAL` | 2（隔帧） | **1（每帧）** | 上升观感要连续 |

空画布（全室温）时 `pendingDrive` 恒 false，`airPass` 仍是 O(1) 退出（验收 A5 保持）。
性能实测：空画布 1.57 ms/tick、95% 填充 6.75 ms/tick、大片岩浆+火 4.11 ms/tick（预算 16.7）。

## A4. 密度交融 / 介质阻尼（反馈②）

### A4.1 模型

旧实现「只要目标格密度更小就 100% 换过去」，等于真空自由落体。
改用 Stokes 终速的离散近似 —— 净加速度 `a = g·(ρ_self − ρ_med)/ρ_self`，于是移动**概率**

```
f = |ρ_self − ρ_med| / ρ_self         （分母恒为「运动物体自身」）
```

- 目标格为 `AIR`（真空）→ `f = 1`，**手感不变**；
- 水(1000) 沉入油(900) → `f = 0.10`；
- 沙(1600) 沉入水(1000) → `f = 0.375`。

### A4.2 为什么用「闸门」而不是逐方向乘 f

最初在正下 / 斜下 / 水平各乘一次 f，结果 0.10 + 0.09×2 + 0.072×2 叠加回 ≈0.36，
实测阻尼比只到 **0.61**（肉眼几乎看不出）。改为 `mediumGate`：
先按正下方介质算 f，再以概率 f 决定「这一格这一 tick 是否允许移动」，
后续方向恢复原始概率 —— **整体速度严格 = f × 原速度**。

### A4.3 同种同温介质必须静止

`f` 在 `Δρ = 0` 时必须返回 **0**，否则同种同温液体会无休止地自我搅拌
（实测水柱内部乱翻，且把「水沉油」的阻尼比从 0.10 抬到 0.65）。
此状态记为 `stalled`：禁止下沉 / 斜下 / 水平，**但保留上浮通道**（热对流要靠它）。

### A4.4 实测

| 场景（120 tick，未触底） | 真空 | 介质中 | 阻尼比 |
|---|---|---|---|
| 水下沉 | 75.0 格 | 油中 **16.5 格** | **0.22**（v1.1 = 1.00） |
| 沙下沉 | 75.0 格 | 水中 **33.1 格** | **0.44**（理论 0.375） |

## A5. 液体热对流 + 导热系数修正（反馈③）

### A5.1 热对流

液体/气体的**有效密度**随温度膨胀：`ρ_eff = ρ · (1 − β·(T − T_amb))`，`BUOY.THERMAL_BETA = 0.0012`。
上下交换判据改用 `ρ_eff` 比较 → 锅底热水自动上浮、表层冷水下沉，形成对流环。

- β 为**放大值**（真实水 0.0002），目的是让 80 K 温差产生约 10% 密度差、在 320×180 网格上可见；
- 仍保证 100 ℃ 水（ρ_eff ≈ 904）**重于**油（900），不破坏油水分层；
- 同种液体之间无分层顾虑，给更高下限 `SAME_CONVECT_MIN_F = 0.25`，让对流跑得动。

实测（金属锅，600 tick）：锅内**下层 87 ℃ / 上层 86 ℃** —— 温差 ≤1 ℃，即对流把热量搬匀了。

### A5.2 导热系数修正

| 元素 | v1.1 `k` | v1.2.0 `k` | 说明 |
|---|---|---|---|
| METAL | 0.90 | **8.00** | 真实铁 ≈80，取 1/10 量级；`α·K·4 = 0.16 < 1` 稳定 |
| WALL | 0.10 | **0.60** | 玩家常用墙当容器壁 |
| STONE | 0.25 | **0.80** | |
| GLASS | 0.20 | **0.80** | |
| WATER | 0.40 | **0.60** | 真实值 |

不取 `k=80` 是因为会让金属与水在 2 tick 内均温，观感失真且逼近震荡边界。

### A5.3 火焰的等效热容

`volHeat[FIRE]` 若按 1100×0.3 计算只有 330，火一碰到空气就被冷却到室温、燃烧蔓延随即失效。
火焰是**持续化学反应放热**，给它等效热容 `1.0e6`（≈水的 1/4）代表放热反应对温度的钳制。

### A5.4 热平衡

长时间大热源（200×120，大片岩浆+火）：
`t=600 空气均温 54 ℃ / 峰值 726 ℃` → `t=2000: 33 ℃ / 129 ℃` → `t=6000: 21 ℃ / 22 ℃`。
**不失控**，散热路径（环境弛豫 + 顶部天空热沉）仍然有效。

## A6. 蒸汽冷凝：改为接触成核（反馈④）

详见 `docs/CONDENSATION-MODEL.md`。要点：

- `ENV_RELAX_GAS` 0.004 → **0.0006**（旧值每秒失约 21% 温差，蒸汽刚离水面就被「吹冷」）；

# 附录 B — v1.2.1 修订（2026-10-13）：燃烧穿透性

> 本章修的是 v1.2.0 配对实验重跑后剩下的 **21 条 REACTION 类 FAIL**，
> 它们全部挂在同一个标题下：「火离开燃料」。追查后发现**标题是错的** ——
> 火并没有"飘走"，真正堵住燃烧的是另两处。故本章独立成篇，优先级高于 §A5 关于火焰的描述。

## B1. 三条独立的根因

| # | 根因 | 表现 | 修法 |
|---|---|---|---|
| R-1 | **锚定判据排除可移动燃料** | 手绘火苗贴着油/粉尘/种子时仍按气态上浮，1 tick 飘走 → small 档 DUST/OIL/SEED × FIRE 全灭 | `movement.js::adjFlammableSolid` 判据由 `!E.movable` 改为 `E.state !== 'gas'` |
| R-2 | **燃烧产物堵死氧气通道** | 烧尽多半变 ASH（固体占位），实心燃料块内部 Chebyshev-2 内永远无 AIR → 只烧掉 27~37% 就自灭 | `FUEL.channelP` 普遍上调（见 §B3） |
| R-3 | **热解引燃未建模** | 燃料被烤到燃点后自身热解出可燃气体，本不需要外界氧气渗入，但旧判据仍要求 `hasOxygen` | `reactions.js`：温度 ≥ `ignitionTemp` 时豁免氧气前置门槛 |

## B2. 为什么「火离开燃料」这个标题是错的

先按标题去修——提高火焰换热系数 `FIRE.conductivity`，结果**完全无效**：

| FIRE.k | WOOD 烧掉 | DUST 烧掉 | COAL 烧掉 |
|---|---|---|---|
| 0.10（原） | 37% | 34% | 27% |
| 0.5 | 36% | 43% | 27% |
| 1.0 | 35% | 37% | 26% |
| 2.0 | 34% | 30% | 25% |
| 4.0 | 40% | 36% | 26% |

再直接测量 24×24 木堆里「紧贴火焰的木料」的温度与通氧情况，才看清真正的死锁：

| tick | 木料残留 | 火焰数 | 贴火的木料格数 | 其中满足 `hasOxygen` 的 |
|---|---|---|---|---|
| 50 | 537 | 39 | 27 | 11 |
| 200 | 503 | 53 | 24 | 8 |
| 600 | 396 | 42 | 10 | **2** |
| 1000 | 362 | 3 | 0 | 0 |
| 1500 | 362 | **0** | 0 | 0 |

即：**火没有飘走，是就地烧完后熄灭的**。火焰始终贴着木料，只是"贴着也点不着"——
因为蔓延判据要求燃料格 Chebyshev-2 内有 AIR，而实心块内部深处根本没有。

## B3. channelP：燃烧的主产物是空腔，不是灰

`FUEL.channelP` = 烧尽后开 AIR 通道的概率（否则变 ASH）。原值 0.2~0.8 让灰占了多数，
灰是固体占位，把氧气挡在外面，于是火烧掉一层就再也进不去。

物理依据：木材燃烧时绝大部分质量变成 CO₂ 与水蒸气**逸出**，灰分只占干重 **1~5%**；
煤灰分较高（5~15%），故 COAL 的取值低于 WOOD 但仍需打开通道。

| channelP（WOOD/DUST/SEED） | WOOD 烧掉 | DUST 烧掉 | SEED 烧掉 | COAL 烧掉 |
|---|---|---|---|---|
| 0.50（v1.2.0） | 37% | 34% | — | 27% |
| 0.85 | 74% | 52% | 59% | 39% |
| 0.90 | 83% | 47% | 69% | 40% |
| **0.95（采用）** | **97%** | **77%** | **92%** | 43% |
| 1.00 | 99%（灰仅 4 格） | 100% | 100% | 33% |

取 **0.95**：既烧得透（97%），又留下可见的灰（约 37 格 / 576，6%），
比 1.00 的"几乎无灰"更有观感，也比旧值符合真实灰分比例。

最终取值：

```
WOOD  0.95   COAL 0.75（煤灰分高）   OIL 1.00（燃尽无残渣）
PLANT 0.95   DUST 0.95   SEED 0.95   VIRUS 0.90
```

## B4. 热解引燃（R-3）

燃料被邻近火焰烤到燃点后会**自身热解**出可燃气体（pyrolysis），这一步不需要外界氧气渗入。
故在 `reactions.js` 的蔓延分支中，把温度判据提到氧气判据之前：

```js
var pyro = grid.temp[n] >= fe.ignitionTemp;
if (needsOxy && !pyro) {
  if (!hasOxygen(grid, n)) continue;   // 冷燃料仍需通气
  ...
}
var pign = pyro ? 1.0 : spreadP * bias;
```

氧气约束改由 `ignite()` 内的 `consumeOxygenNear` 承担：真缺氧（4 邻无 AIR）时不耗氧，
配合 §9.6 持续耗氧，密封自熄的红线仍然成立（测试 V9）。

## B5. 修复后实测

| 场景 | v1.2.0 | v1.2.1 |
|---|---|---|
| small（1 格 DUST/OIL/SEED + 1 格火苗） | 全部点不着（6/6 FAIL） | **全部烧掉（6/6 PASS）** |
| 24×24 WOOD | 37% | **95%** |
| 24×24 DUST | 34% | **77%** |
| 24×24 SEED | 36% | **92%** |
| 24×24 OIL | 100% | 100% |
| 24×24 COAL | 27% | 47%（仍在燃烧，煤难烧合理） |

## B6. 红线复核（不得因放宽而破坏）

| 红线 | 判据 | 实测 |
|---|---|---|
| 开放 100% 蔓延 | 80 格木条一端点火，3000 tick 后残留 | **0 / 80** ✅ |
| 密封自熄 | WALL 盒内 18×18 木料中心点火，残留 ≥300 | **323 / 324**，FIRE=0 ✅ |

两条红线在放宽氧气判据与上调 channelP 后**均保持成立**——

# 附录 C — v1.2.2 修订（2026-10-13）：TNT 引爆与煤的燃烧穿透

> 本章修的是 v1.2.1 配对实验重跑后剩下的 **12 个 FAIL 判定组**中，
> **不需要新增元素**即可解决的两类：`LAVA × TNT` 与 `COAL × FIRE`。
> 其余（SALT×WATER 溶解不守恒等）需要新增元素，另见 §C4 待决策清单。

## C1. LAVA × TNT：不是热量不够，是接触时间不够

旧引爆判据（`reactions.js::explosionPass`）：

```js
if (grid.temp[i] >= 180 || adjFire(grid, i))   // 自身达 180℃ 或 4 邻有 FIRE
```

追测量（small 档，1 格岩浆 + 1 格 TNT，seed=1337）：

| tick | LAVA 温度 | TNT 温度 |
|---|---|---|
| 1 | 1192 | 24 |
| 20 | 1095 | 23 |
| 100 | 754 | 49 |
| 200 | （已凝固为 STONE） | **152** |
| 600 | — | 52 |

**TNT 历史最高温仅 152℃，永远够不到 180℃**。根因不是传热系数太小——
LAVA 是液体，落在地面上会立刻横向铺开，与 TNT 的有效接触只有 1~2 tick，
之后邻接关系就断了，TNT 只能靠已被加热的空气慢慢捂热，而岩浆自己先凝固成 STONE。

现实中这显然不成立：TNT 自燃温度约 160~200℃，被 1200℃ 岩浆接触**必然瞬爆**。

### 修法

把「自身温度」放宽为「**接触面温度**」——即 4 邻域内存在达到自燃点的热体即可引爆：

```js
var TNT = { ...,  IGNITE_T: 180 };
if (grid.temp[i] >= Balance.TNT.IGNITE_T || adjFire(grid, i) || adjHot(grid, i))
```

`adjHot()` 检查 4 邻域中是否有**非 AIR** 且温度 ≥ `IGNITE_T` 的格子（岩浆、明火、炽热金属都算）。
排除 AIR 是必要的：空气被岩浆烤热后经 `airPass` 上升，会在 TNT 周围形成几百度的热羽，
若把 AIR 计入，TNT 就会被"路过的一缕热气"引爆，明显过头。

### 实测

| 场景 | v1.2.1 | v1.2.2 |
|---|---|---|
| LAVA × TNT small（seed 1337 / 2024 / 777） | 0 / 3 引爆 | **3 / 3 引爆** |
| 对照：35 格外的 500℃ 岩石 | 不引爆 | **仍不引爆**（判据没有放宽过头） |

## C2. COAL × FIRE：实心煤块烧不透

24×24 = 576 格煤块贴着一整面火焰，1200 tick 后三种子分别残留 **338 / 324 / 300**，
只烧掉约 50%，且结束时仍有 77 格火在烧——不是"点不着"，是**蔓延太慢**。

煤的 `spreadP = 0.04` 是所有燃料里最低的（作为"难点燃"的设定是合理的），
但 `channelP = 0.75` 让烧尽的格子里有 1/4 变成 ASH 占位，进一步拖慢内部蔓延。

| channelP / spreadP | seed1337 | seed2024 | seed777 | 密封木室红线 |
|---|---|---|---|---|
| 0.75 / 0.03（v1.2.1） | 338 | 324 | 300 | 323 / 324 ✅ |
| 0.85 / 0.06 | 235 | 258 | 253 | 323 ✅ |
| **0.85 / 0.09（采用）** | **195** | **231** | **237** | **323 ✅** |
| 0.90 / 0.09 | 187 | 234 | 210 | 323 ✅ |

采用 **0.85 / 0.09**：烧掉约 60%（"大部分"），煤仍明显比木材（95%）难点燃、烧不透，
保住了材质区分度；密封自熄红线未受影响（323/324，火全灭）。

## C3. 本附录引入的参数

```
FUEL.COAL.spreadP  = 0.09  // 0.04 → 0.09
```

| **所有熔融统一变 LAVA** | 金属/盐/玻璃熔化都变成"岩浆" | 需新增 `熔融金属 MOLTEN_METAL`、`熔融玻璃` 等；与"30 种元素"的既有约束冲突 |

以上三项都**突破 30 元素上限**，且会改变元素面板与存档格式，需用户拍板后才动手。

# 附录 D — v1.3.0 / v1.4.1 修订（2026-10-15）：液体铺展与表面流

> 冲突时**以本附录为准**。相关代码：`src/core/movement.js`（液体分支、`mediumGate`）、
> `src/core/balance.js`（`LIQUID`、`SOIL`）、`src/core/elements.js`（SEED.density）。

## D1. 薄液膜阻尼（v1.3.0）

单格孤立液滴的水平铺展概率乘 `LIQUID.FILM_SPREAD_F = 0.12`（判据：上方无液体压力
**且** 左右下均无同种液体）。物理依据：重力驱动的横向流量 ∝ h²（泊肃叶流），
自由表面薄层受壁面摩擦与表面张力阻滞几乎不流。连续液膜（左右/下方有同类）不受影响，
找平、连通器、灌注等宏观行为保留。

## D2. 液体停滞规则（v1.2.0 引入 → v1.4.1 修正）★

**v1.2.0 的规则**：`mediumGate` 判定"正下方是同种同温液体"时返回 0（净浮力为零），
液体分支随即 `if (stalled) return;` —— 该格本 tick **全部**移动被否决。

**用户实测的后果（"水现在像沙子一样，我放下去就堆在那里，油也是"）**：
落到水面/池面的水，同种格不能互换（`enterableSide` 要求目标密度更小）、
下方同温不能下沉（防止自我搅拌）、侧移又被 stalled 否决 → 只能**垂直堆叠**，
且堆成的塔永不瓦解。复现数据（80×60，池面 y=40）：

| 场景 | v1.4.0 及以前 | v1.4.1 |
| --- | --- | --- |
| 池面倒 5×5 水，300 tick | 仍留 **6 格高塔** | 堆高 **0** |
| 空投 15 格水柱，400 tick | 仍留 **15 格高塔** | 堆高 **0** |
| 池面倒 5×5 油，300 tick | 6 格油塔且几乎不动 | 铺成薄膜（≥10 列） |

**v1.4.1 修正**（三处，语义不许再改）：

1. **`stalled` 只禁下沉**：`if (stalled) return;` 删除；下沉仍由 `!stalled` 把关。
   表面流（斜下/水平）对 stalled 格放行，但**仅允许进入 AIR**（`(!stalled || el[j] === 1)`）。
   理由：塔的瓦解路径是"顶层向 AIR 塌落、层层剥离"；而进入其他液体的移动仍由沉降阻尼管，
   保持"水沉油慢十倍"的手感。同种格永不互换（密度判据）→ 不重新引入自我搅拌
   （v1.2.0 的原始顾虑）。
2. **漂浮旁路**：`mediumGate` 中若运动格**轻于**正下方介质且下方是**液体** → 返回 1（不阻尼）。
   物理：漂浮体不沉降，Stokes 阻尼不适用；油膜在水面的铺展由表面张力驱动，旧值
   （油浮水 f=0.11）把 89% 的 tick 直接掐掉。**仅对下方是液体生效** —— 水在沙/土上
   仍按沉降因子阻尼（V6 实测：放开后水会冲离苗根导致植物停长）。
3. **轻液爬行 `LIQUID.CREEP_F = 0.3`**：漂浮在**更重液体**上（`did === tj2`，即正下方就是它）
   的轻液，水平方向可挤入该更重液体（概率 `mobility × 0.8 × CREEP_F × filmF`）。
   重液被挤开后会因密度判据自行沉回 → 油水分层不破坏（V3 仍过）。

## D3. 配套生态参数调整（v1.4.1）

表面流让水滩更快流走，暴露了两个生态参数欠账：

| 参数 | 旧值 | 新值 | 理由 |
| --- | --- | --- | --- |
| `SOIL.MOISTURE_MAX` | 200 | **400** | 土壤是真正的蓄水层 |
| `SOIL.MOISTURE_GAIN` | 2 | **6** | 接触水时快速饱和（≈67 tick 满） |
| `SOIL.DRY_RATE` | 1 | **0.25** | 湿土长效（≈1600 tick）；旧值 200 tick 就干透 |
| `SEED.density` | 800 | **1050** | 略重于水、入水沉底：旧值种子浮在水面被流动的水推着走，发芽延迟 1000+ tick |

实测：V6 主柱高度 21-23 → **35**（种子不再漂移、根区湿度维持）。

# 附录 E — v1.5.0：找平/传热/凝结三处提速（2026-10-15）

> 背景：用户实测「水的找平还是太慢」「用火加热烧水还是太慢」「一堆只有 20 度的水蒸气」。
> 本轮全部先**量化定位**再改（`_diag_flat*.js`、`_diag_pour*.js`、`_diag_boil2.js`）。

## E1. 液体找平（movement.js 液体分支）

| 机制 | 作用 | 参数 |
| --- | --- | --- |
| **下坡偏置** | 表面格用有界下探（≤6 格）比较左右邻列的水面深度，**优先朝更低一侧铺展**；两侧等高才随机。旧实现左右各 50% → 净输运≈0、找平退化成 √t 扩散（实测 320 宽大池 3000 tick 仍起伏 ≥4 格） | 内联 |
| **连通水体流速拉满** | 属连通水体（左右下任一同类）的表面格铺展概率 ×1.15 → 封顶 **1 格/tick**（旧值一律 0.72）；孤立液滴仍走 `FILM_SPREAD_F=0.04`（表面张力钉住） | `LIQUID.FLOW_K` |
| **冲流级联** | 铺向 AIR 后若脚下仍空 → **连续下落直到落到液面**（≤4 格）。只落一格会留下"悬浮薄层"（同温同种禁止下沉）→ 长期拉大起伏、找平停滞 | `LIQUID.CASCADE` |
| **水面滑移** | 已在液面上（脚下不是空的）→ 前方仍 AIR 则再滑一格（≤2 格/tick） | `LIQUID.SLIDE2` |

**实测**：40×26 的水堆在 318 宽容器内铺满由 **>900 tick 降到 ~420 tick**（提升约 2×）；
`_diag_pile.js` 倒水入池堆高恒为 0。**残留限制**：元胞自动机中"完全平坦的水面"没有任何
可进入的空气格，跨平台面的输运只能靠台阶列，故最终水位仍可能残留 1-2 格差（视觉上近水平）。
这是 CA 的固有限制，非缺陷。

## E2. 火焰传热与点火可靠性（thermal.js）

- **火焰接触传热系数** `FIRE.CONTACT_K` 0.06 → **0.10**；热气体对流传热 `GAS_CONTACT_K` 0.05 → **0.08**。
- ★**关键修复**：`contactFlux` 原本把**可燃物一律排除**在传热目标外（为守密封盒红线），
  导致点火只能靠 `spreadP≈0.05/tick` 掷签 —— 实测 8 个种子里 2 个点不着，
  用户"锅下生火 → 木柴点不着 → 火 40 tick 就灭 → 锅几乎不热"。
  新判据：**燃料自身通气（`hasOxygen(燃料格)`）即允许被火焰烤热**。
  - 露头燃料 → 被烤到燃点 → 正常引燃（实测**首次沸腾 t=127 = 2.1 秒**）；
  - 厚燃料块内部 / 密封盒内（无氧）→ 不加热 → 不引燃 → 自熄（N1-4/N1-8/V9 红线全部保持）。

## E3. 过冷蒸汽必须凝结（transitions.js）

- 新增 `STEAM.HOMO_FULL_T = 50`：**低于 50°C 的蒸汽不再享受"缺冷核"折扣**，按全速率凝结。
  物理：过冷蒸汽在任何壁面/微粒上都凝结；只有接近饱和（~100°C）才需要凝结核慢慢来。
- 实测：70 格 20°C 蒸汽在 900 tick 后**残留 0 格**（旧实现长期悬浮 —— 用户「一堆只有 20 度的水蒸气」），
  而 90°C 的热蒸汽仍按成核模型缓慢凝结、升顶逸出（V5(a) 保持）。
