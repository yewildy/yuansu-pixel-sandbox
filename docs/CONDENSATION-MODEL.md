# 冷凝模型（v1.2.0）— 蒸汽 → 水

> 唯一真源：`src/core/transitions.js`（case 23 STEAM）+ `src/core/balance.js::STEAM`。
> 上游：本文档是 `docs/PHYSICS.md §7.2` 的**替换件**，冲突时以本文为准。
> 参照：Powder Game（DAN-BALL）—— 它的 STEAM 根本不变水，变水的是 CLOUD，且必须**碰到 block/固体**才触发。

---

## 1. 问题：v1.1 的蒸汽「一秒变雨」

用户实测原话：

> 水蒸气受冷过程是不是太快了，立刻就会变成水滴下来非常不合理。

v1.1 的规则只有一条：`T < 100` 就按 `p = COND_COEF·(100 − T)` 凝结。配合 `ENV_RELAX_GAS = 0.004`，
蒸汽离开水面后被空气以**每秒约 21%** 的速率吹冷（半衰期约 3 tick），
于是整片蒸汽在 1 秒内全部变成水砸下来 —— 观感是「开水冒雨」而不是「开水冒汽」。

两条成因缺一不可：

| 成因 | 数值 | 后果 |
|---|---|---|
| 气体散热过快 | `ENV_RELAX_GAS = 0.004`（暴露 ×2 → 0.008/tick） | 蒸汽 3 tick 就被吹到室温 |
| 冷凝无成核条件 | 只看自身温度 | 悬在半空的蒸汽也会成水，直接变成雨 |

---

## 2. 修复一：气体散热速率

```
PHYS.ENV_RELAX_GAS:  0.004  →  0.0006
```

理由：空气本身是热的不良导体（k≈0.026），悬浮在空气中的蒸汽团没有理由几帧就被吹到室温。
改后半衰期约 1150 tick（≈19 s），蒸汽可以正常上升、飘散、或被顶部热沉处理。

---

## 3. 修复二：接触成核（非均相成核）

### 3.1 物理依据

现实中的水蒸气凝结绝大多数是**非均相**的 —— 需要凝结核（尘粒、器壁、液膜）。
在纯净空气中，均相成核需要极大的过饱和度，速率要低好几个数量级。
宏观表现就是：**水蒸气可以在空气中飘很久，但一碰到冷玻璃/锅盖就立刻结出水珠。**

Powder Game 用了一个等价的离散做法：STEAM 不会变水；独立元素 CLOUD 变水，
且触发条件是「碰到 block 和 solid 元素」（玻璃、带电玻璃、冰、克隆体、金属除外；碰冰变雪、碰金属变雷）。

### 3.2 实现

`transitions.js::hasColdNucleus(grid, i)`：4 邻域存在**非气体元素**（`state !== 'gas'`）
且其温度 `< STEAM.NUCLEUS_COLD_T (95 ℃)` → 判为冷核。

```
p = clamp(COND_COEF · (100 − T), 0, COND_P_MAX)
if (!hasColdNucleus(i)) p *= STEAM.HOMO_F      // 0.2：均相成核折扣
```

- `NUCLEUS_COLD_T = 95 ℃`：**热水面不算冷核**，否则水一沸腾、上方的蒸汽立刻被自己凝回去，水永远烧不开；
- `LATENT_TICKS_COND: 6 → 24`：潜热平台，给蒸汽一段必须「放热」的时间（0.4 s）；
- 仍保留 `T ≥ 100` 恒不冷凝的硬闸（§7.2）。

### 3.3 参数

| 参数 | v1.1 | v1.2.0 | 含义 |
|---|---|---|---|
| `STEAM.COND_COEF` | 0.00015 | 0.00015 | **有冷核时**的凝结系数（T=20 ℃ → p≈0.012，半衰期约 1 s） |
| `STEAM.HOMO_F` | — | **0.2** | 无冷核折扣（等效 0.00003，半衰期约 5 s） |
| `STEAM.NUCLEUS_COLD_T` | — | **95 ℃** | 冷核温度上限 |
| `PHYS.LATENT_TICKS_COND` | 6 | **24** | 冷凝潜热平台 |
| `PHYS.ENV_RELAX_GAS` | 0.004 | **0.0006** | 气体散热速率 |

## 5. 玩家可见的现象（预期）

- 烧水 → 蒸汽柱上升 → 在半空**保持气态**、逐渐变淡 → 碰到冷的锅盖/天花板才在**顶壁结出水珠**并沿壁滑落；
- 冰面附近的蒸汽 → 凝成**雪**（由 ICE 的既有规则处理）；
- 蒸汽若一路升到画面顶部 → 从顶部逸出（§13.3 vent），不会积在天上。

# 6. v1.5.1 重做：从「固定计时器」到「纯温度驱动」★

> 用户实测（第三轮）：「另外还有一堆只有 20 度的水蒸气，似乎水变成蒸汽后就是固定时间会回归，
> 而不是等冷却再凝结成水。」「我要求你把它变为水蒸气是一百度以上的，等冷到什么温度才会落下去，
> 就是要水的温度是有连贯性的，不然上去后马上又下来又要从 20 度再加温，这是有问题的。」

## 6.1 根因：温差被瞬间抽干（`_diag_steam.js` 实测）

`thermal.js::diffuse` 的体积热容加权公式是给**固态/液态**导热量身定做的。气体代入后
`r = α·K·C_REF·(Ci+Cj)/(Ci·Cj)` 算出 ≈ 2（远超上限），被钳到 `CONDUCT_R_MAX = 0.2` ——
**等于"气体之间瞬间均温"**。实测（v1.5.0）：

| 场景 | v1.5.0 实测 |
| --- | --- |
| 单格 100 °C 蒸汽在 20 °C 空气中 | **1 tick → 67.9 °C；10 tick → 20 °C** |
| 10×6 的 100 °C 蒸汽团 | 30 tick 后平均 **21 °C**；90 tick 全部凝结 |
| 烧水的蒸汽羽流（178 格） | 温度 min/mean/max = 26/33/143，其中 **159 格低于 40 °C** |
| 70 °C 水面（表面蒸发路径） | 产出 43.5 °C 的"蒸汽" |

后果是**温度毫无连贯性**：水在锅里烧到 100 °C → 变成蒸汽 → 蒸汽 10 tick 内被空气倒空显热变成
20 °C 的"冷蒸汽" → 因为 T < 100 被判凝结 → 凝成 20 °C 的水落回锅里 → 下次沸腾又要从 20 °C 加热。
玩家的观感就是"蒸汽是 20 度的"和"固定时间自动变水"（后者来自 `LATENT_TICKS_COND = 24` 的固定计时器）。

## 6.2 三处修改

### ① 气体热惯性 `PHYS.GAS_GAS_R = 0.006`（thermal.js）

除「空气-空气」（沿用 `AIR.SELF_R = 0.0015`）与「火焰」（FIRE 必须继续快速加热空气，
否则 v1.4.0 修好的「火 → 热空气 → 锅底」传热链会断）之外，**气-气配对**改用热惯性松弛因子。
物理依据：气体是可压缩可掺混的气团，热量搬运主要靠对流位移（`air.js::airPass` 的物质搬运），
分子导热只占极小部分。时间常数 ≈ `1/(2r) ≈ 83 tick`。公式形式不变 ⇒ **严格守恒 Σ C·T**。

### ② 凝结：删除 tick 门槛，改饱和温度 + 过冷度（transitions.js）

| 规则 | 说明 |
| --- | --- |
| `T ≥ COND_T (100 °C)` | 过热蒸汽，**不凝结**（只有冷却能触发相变） |
| `T ∈ [COND_T-3, COND_T)` | **潜热平台**：凝结放热把温度钉回饱和温度 ⇒ 凝出的水就是 ~100 °C |
| `T < COND_T` | `p = COND_P_BASE(0.05) + COND_P_SLOPE(0.004) × 过冷度`，**无 tick 门槛** |
| 近饱和窗口（过冷度 < 20 °C） | 缺凝结核 → ×`HOMO_F(0.2)`，给羽流上升时间（不再锅口即落） |
| 深度过冷（过冷度 ≥ 20 °C） | 不再打折，任何地方都凝结（物理：均相成核；也保证没有 20 °C 蒸汽悬浮） |

删除：`LATENT_TICKS_COND`（固定 24 tick 计时器）、`HOMO_FULL_T`（被 `NUCLEUS_WINDOW` 取代）。

### ③ 删除「低于 100 °C 的表面蒸发」路径（transitions.js / balance.js）

旧路径让 60–99 °C 的水直接变成同温度的 STEAM，违反用户要求的不变式「水蒸气是一百度以上的」，
且那种蒸汽一生成就低于饱和温度、按温度判据立刻又凝结回去，纯属来回空转。
现在 **STEAM 的唯一来源是沸腾（T ≥ 100 °C）**，蒸汽生成温度必然 ≥ 100 °C。
（物理上 60 °C 的水确实会蒸发，但那是看不见的水汽，应并入空气湿度场 —— 本作没有湿度场；
STEAM 元素代表可见白汽，与原版 Powder Game 一致。）

# 7. v1.6.0：潜热预算 —— 蒸汽成为"热载体"

v1.5.1 解决了蒸汽的**温度连贯性**，但留下了用户实测的新问题：
「空气并不能被水蒸气加热 … 往上跑的水蒸气永远有一堵墙，到了一定高度就会被冷却，
而更上方的空气还是没有被加热充分」。完整诊断与扫描见 **docs/PHYSICS-AIR.md 附录 G**。

**核心补充**：蒸汽现在自带 `LATENT_MAX = 255` 的**凝结潜热预算**。

| 环节 | 规则 |
| --- | --- |
| 生成 | 沸腾（`transitions`）、岩浆淬水/汽化（`reactions` ×2）、画刷、读档 —— 全部发满预算 |
| 每 tick | 若 `lat > 0` 且 `T < COND_T`：`lat -= (COND_T − T_post_diffuse)`，并把 `T` 钉回 100 °C |
| 预算耗尽 | 回到 v1.5.1 的温度驱动凝结（过冷度越大越快），并在 1–3 tick 内凝结落下 |

**为什么这样能同时满足过去两条要求**：
- "蒸汽必须 ≥100 °C / 不能变 20 度" → 有潜热时温度被钉在饱和温度 ✓
- "要冷到什么温度才落下去 / 不要固定时间" → 凝结时机由**预算耗尽**决定，而预算消耗速率
  ∝ 与周围空气的温差 ⇒ **周围越冷越早落下、空气越暖升得越高** ✓
- "空气必须被蒸汽加热" → 交给空气的热量 = 潜热预算（≈4× 显热量）✓

**实测**（持续沸腾 3000 tick）：上部空气 26.9 → **44.6 °C**；凝结高度中位 162 → **114**；
羽流天花板 y=87 → **30**；锅内水 0/392 → **194/392**；凝结高度随时间抬升（10% 分位 83 → 67）。

**已知近似**：预算有限（不是无限热源）；`latent` 不入存档（读档重建）；
顶部边界仍是主要散热口（见附录 G6 关于"严格浮力判据"的回退记录）。
