## 2. 机制原理（含完整 why 链）

### 2.1 为什么必须是「整条通道一步」

满格晶格上**任意割集的净通量恒等于 0**：一次 swap 必然同时 +1 和 −1。
推论：**任何"每格独立掷骰"的定向输运，期望值恒为 0**——交换次数能涨到 17 万格次，示踪剂却只做 √t 扩散。
本项目的失败清单（`ROW_REF_R / WALL_SPREAD_* / WALL_SCAN / WALL_PUSH / AMBIG_RATIO / HEAD_K`）全部栽在这条定理上。

两条合法出路：① 闭合环「整环一步」（V35 `ductFlow`，已完成）；② **物质真正离开/进入**（开放系统边界不守恒）。开口烟道走第 ② 条。

### 2.2 链上怎么做到「一步」（与环不同）

链上顺序 swap 只能做出两两转置（净位移 0）或"末端瞬移到首端"（不物理）。
所以不用 swap，用 **`grid.moveTo` 链式前移 + 边界源汇**：

```
for k = len−2 … 0:  moveTo(lane[k] → lane[k+1])
```

`moveTo` 语义 = 内容搬到目标格、源格重置为环境温 AIR。逆序执行 ⇒ 只有 lane[0] 留着重置值（= 大气补气），lane 尾部那格的物质被真正**推进大气**（车道尾部特意延伸 `FLUE_SINK` 格到出口外的开放空间）。进出各 1 格、严格配平，净效果 = 通道内容整体前移一格。

**闸门粒度 = 整条烟道一个骰子**（`air.js::rotateFlue` 里唯一的 `RNG.hash01`），不是每格一个骰子。

### 2.3 驱动力 = 烟囱效应（stack effect），不是逐格浮力

`drive = ½·(b_A + b_B)·(y_A − y_B)`，`b = ρ_rel(T_out) − ρ_rel(T)`，`ρ_rel(T)=(amb+273)/(T+273)`。
A = 较低洞口、B = 较高洞口，y 向下为正。drive>0 → A→B（烟囱）；drive<0 → 整条车道反向（冷气倒灌）。
用**洞口气温**而非整条通道均温：长烟道里 250 °C 烟团只占 3% 体积，均温口径会让抽力趋零、永远起不来。这是**集总稳态模型**（工程上给烟囱定抽力就用供给端烟温），如实记录，不是逐格瞬时力。

### 2.4 几何识别（O(n)，隔 `FLUE_ANALYZE_INTERVAL=8` 帧跑一次）

1. 水平/竖直**气体游程**任一 ≤ `FLUE_MAX_W=12` → 窄通道格（开放空间两个游程都大 → 不命中，开放场景零副作用）；
2. 开放区洪泛（**必须触到画布边界才算大气**——密封房间里不可能有净贯穿流，守恒把它锁死），并吸收**密封气窝**（不触边、贴着通道、体积 ≤ W²）——没有这一步，S 形烟道会在四个转角被切成 5 段碎管（转角腔横竖游程叠加、两个判据都不过）；
3. 最大连通分量 ≥ `FLUE_MIN_LEN=40`；
4. **§3.1 的贴壁率闸门**；
5. 洞口 = 通道格且四邻有真大气；洞口按 4-连通聚类，**必须 ≥2 簇（一进一出）**才接管，否则交还给 `ductFlow`；
6. 抽力 + 车道（净空场 + 阈值扫，见 §3.2）。

## 3. 本轮修掉的三个 bug（都有实测证据）

### 3.1 ★P0：V25 被 FLUE 侵蚀（余水 127 → 110，跌破 30% 门槛）

**根因**（qa-flue 独立复现 + team-lead 决定性实验确认）：「窄通道 + ≥2 洞口」判据会把**开放空气里的上升羽流**也认成烟道——烧水锅上方那股羽流水平游程 ≤ 12，上下都通大气，判据全过 ⇒ FLUE 在锅上方架起一条 776 格的隐形输送带，凭空改写不属于它的输运。
（`FLUE_MAX_W=0` → 127；开启 → 110，差值 100% 归因于 FLUE。）

**修法（机制层面的几何区分，不是调阈值蒙混）**：
1. **「烟道必须由墙围成」闸门 `FLUE_WALL_FRAC=0.8`**：统计通道与外界的 4-邻接接触面里**刚性壁**（`IS_RIGID` = 非气体且不参与通用移动通道，石/墙/金属）的占比，低于 0.8 不算烟道。实测：S 形烟道 **0.97**（贴壁接触面 ≈1000、洞口空气接触面 ≈18）；锅上方羽流 **0.29~0.60** ⇒ 被挡掉。
   为什么数"刚性"而不是"非气体"：V25 的锅里正下着**冷凝水滴雨**，水也是非气体——以水为壁，羽流照样过闸（实测 0.5~0.6）。`movable` 区分很干净：水滴会掉（movable=1），砌出来的墙不动（movable=0）。
2. 结果：`_diag_v25flue.js` 里 FLUE 开 = **余水 127/392、flueMoved=0、有车道帧 0/3600** —— 与 FLUE 关**逐位一致**。

### 3.2 车道数恒为 1（522/4833 格）→ 贯穿效率低

**根因**：车道分解用「净空场 + 阈值扫」，而净空场的种子是"任何非通道格"。入口注烟后通道里结出的**冷凝水滴**也是非通道格，它把周围一圈净空压到 1~2 ⇒ 阈值从 dmax 一路掉到 2 ⇒ 车道重新贴壁 ⇒ 贴壁车道在拐角处**横穿通道截面**，把通道拦腰切断 ⇒ 第二条车道 BFS 永远找不到出口（`dbgTgt=-1`）⇒ 永远只有 1 条。

**修法**：净空场种子**只认刚性壁**（`IS_RIGID`）。水滴/沙粒不参与净空（它们本来就不是车道能走的格），中轴净空恢复 5。车道随即按"中轴 → 次中轴 → … → 贴壁"像削洋葱一样剥离。
**结果：车道数 1 → 3，车道格数 522 → 1596（通道截面的 1/3，其余由 airPass 对流搬运）。**

### 3.3 抽力→概率的标定太肉（`FLUE_DRIVE_SCALE` 8.0 → 4.0）

实测 drive≈4.3，旧标定 p=(4.3−0.5)/8=0.47 ⇒ 推进 0.47 格/tick，且 drive 一波动就出现长停滞（QA 观测到的"停滞 300 tick"）。
新标定 p=(4.3−0.5)/4=0.95 ⇒ 满抽力下 0.95 格/tick（≈57 格/秒）。物理上烟囱抽速 1~5 m/s，一格≈2.5 cm ⇒ 0.95 格/tick ≈ 1.4 m/s，量级正确。

## 6. 对 team-lead 三个质量保留的回应

### 6.1 「脉冲式推进」
原因 = `p = (|drive|−死区)/SCALE` 是概率闸门，drive 随洞口气温波动 ⇒ p 波动。已把 SCALE 8→4（见 §3.3），满抽力时 p≈0.95，停滞段消失（§5.1 前锋逐 100 tick 表里没有 300 tick 级停滞）。剩余的轻微不均匀是概率闸门的本质（真实烟囱也有阵发性抽力），且逐帧质心仍单调。

### 6.2 「贯穿效率只有 1%」
当时确实只有 1 条车道（§3.2 的 bug）。修掉后 3 条车道（1596 格）、满抽力推进：出口窗 1→14 格（持续供烟）/ 1→3 格（烟塞）、首次到达 977→923 tick、前锋 99.2%。剩余的"不是每个示踪格都走完全程"是模型的几何上限：车道顶点不相交，通道截面只有 1/3 在车道上，其余靠 airPass 对流慢慢汇入——与真实烟道"主流道 + 边界层"的结构一致。

### 6.3 「后半程质心回落（疑似入口倒流）」
**真因是示踪剂衰减，不是倒流。** 一次性烟塞的载体是 SMOKE，它有寿命：期末通道内示踪 80 → 24 格（保留率 24%），最靠前的那批先老化消失 ⇒ 质心被往下拉。证据：
- 持续供烟那一遍（不断补新烟）质心 **28.2 → 213.5 单调上升、无回落**（§5.1）；
- 四臂对照里 off/seal/noheat 的净位移都 ≈0；若真有"机制性倒流"，on 与 off 应同号同量级。

## 7. 自判定与保留意见

**自判定：PASS。** 用户要的「流通过左右方向 S 形管道的水汽烟雾截图」已由四帧 PNG + 逐帧数值自证：烟从下层左端进、爬右竖、穿中层、爬左竖、从上层右端冒出，逐帧单调前进。

保留意见（如实记录）：
1. **车道只覆盖 1/3 截面**（`FLUE_MAX_LANES=8` 但实际找到 3 条）。更激进的"全截面平行切片"方案没做——它需要一个全通道无冲突的下游映射，在拐角处会退化，收益/风险比不划算。
2. **热源在通道中段时不驱动**（集总模型用洞口气温，两个洞口都常温 ⇒ drive≈0）。已知上限，已在 balance.js 注释里写明。
3. **`FLUE_WALL_FRAC=0.8` 是经验门槛**：真烟道实测 0.97、羽流 0.29~0.60，中间空隙很大；但一个"半开放凹槽"式的合法烟道（贴壁率 0.7~0.8）会被漏掉。
4. **性能**：分析隔 8 帧 + 无烟道时早退；`FLUE_P_MAX≤0` 时整机制关闭并清理模块级缓存（防上一次运行的残渣污染下一个场景）。N1-9b 空场 / 火场计时项未复测（本轮改动只在识别帧做 O(n) 扫描，且开放场景在 ① 步 `nCor<minLen` 即退出）——**这条留给 QA 的计时项确认**。
5. 诊断接口 `flueDbg()` 从 9 项扩到 **12 项**（新增贴壁率%、dmax、th），qa 的复刻诊断若按旧 9 项解析需要注意。
