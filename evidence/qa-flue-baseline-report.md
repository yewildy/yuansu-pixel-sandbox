1. **窄通道判据把管腔切碎**：拐角处竖直游程 43 格、水平游程 165 格都 > `FLUE_MAX_W=12` ⇒ 拐角格既非 narrowH 也非 narrowV ⇒ 蛇形通道在 4 个拐角断成 5 段。

## 3. 测量设计（为什么这些口径才有效）

### 3.1 避开的三个陷阱（全部落实）

1. **不量割集净通量**（恒等于 0）：只量拉格朗日量 —— `grid.tint` 上的标记值 `200` 作为染料。
   tint 只被 `swap`/`moveTo` 搬行（已在 `src/` 全量 grep 确认只有这三处触碰 tint），
   不被反应/相变/寿命逻辑改写；`clear()` 只生成 0–4，所以 200 是干净的、**不会衰变**的
   拉格朗日染料（SMOKE 会衰变、STEAM 会凝结，都不能直接当示踪）。
2. **churn（交换次数）只记录、不判定**：本轮 on 臂 churn = 239.8 万格次，而示踪前锋只走到 11%。
   数字放报告里是为了"对照别人拿 churn 说事时能当场打脸"。
3. **只认单一窗 / 边界逃逸，不做多段求和**：硬证据 = 「出口窗」（弧长 ≥ S_MAX−8 的 45 格）+
   「排气区」（出口外上方 x≥179, y≤40）的累计逃逸格数。

### 3.2 示踪口径的一个重要发现（我自己踩到并修掉的假象）

入口是敞开的，示踪会有一部分**从入口倒流回外部开放空间**（期末 74/98 = 76% 跑到通道外）。
若只统计"仍在通道内"的示踪质心，被剔除掉的恰好是**最靠后**的那一批 ⇒ 质心被系统性抬高
⇒ **读出假的正漂移**（"只算通道内"口径给出 Δ=+20.9 格 / 4.0%，看似在推进）。

修法：加一个**保守口径** `meanAll` —— 分母含跑到通道外的（按弧长 0 计入），
只会低估推进。用它判定。**这个假象很容易被别人当成"有流"的证据，请主理人转告 eng-flue 别栽在这上面。**

### 5.2 机制层面的根因判断（供 eng-flue 参考，不是他的结论）

`src/core/air.js::ductFlow` 的整环一步机制**结构性不适用于开口烟道**：
- `analyzeDuct` 第 1 步做闭空腔洪泛，**触及画布边界者排除**（`cavOK=0`）；
- 开口烟道通过入口/出口连到外部开放空气，整片开放空气是一个触及边界的巨大气体域
  ⇒ `closed === 0` ⇒ `cycCount = 0` ⇒ 直接退出（`air.js:286`）。
- 这不是 bug，是**设计上的能力边界**（balance.js 里也写明"只处理未触及画布边界的闭合空腔"）。
  所以 V35（闭合环 87/0）通过 ≠ 开口烟道能流。**eng-flue 需要为开口几何新写机制**，而不是调 DUCT_* 参数。

另外两个实测的"堵点"（对设计新机制有用）：
- `airPass` 的贴壁输运要求 `d > BUOY_DT`（`air.js:595` 的未驱动分支直接 `continue`）；
  气团沿 160 格的水平通道走，一路把热导给墙，走到一半就掉回 `d ≤ BUOY_DT` ⇒ **停在原地**。
  这正是前锋卡在 58（≈ 加热片上方 + 一小段）的原因。
- 空腔分类 `scanCavities` 是**按列**的 `gasUp/gasDn`：烟道浮在开放空气里，每一列上方/下方都有
  开放空气 ⇒ `gasUp=gasDn=1` ⇒ `corr=0` ⇒ 既不算"空腔顶"也不算"空腔底"，水头推送 `WALL_PUSH`
  **在这个几何里一次都不会触发**（`air.js:568` `if (pushOn && corr)`）。

## 6. 与 eng-flue 结论的对照 / 我发现的坑（最有价值的部分）

1. **「示踪最远弧长」这个口径会被入口泄漏污染。** 他给的基线"20/557 = 3.6%"用的是最远点；
   我实测前锋峰值 58/519 = 11.2%（差 3 倍）。两者都对（几何参数化不同 + 注入位置不同），
   但**"最远点"是个噪声极大的统计量**（单格、会被对流随机推远）。建议统一用
   「**出口窗到达**」做硬证据、「**保守净位移**」做趋势证据，别用最远点。
2. **"只算通道内"的质心会假阳性。** 详见 §3.2，Δ=+20.9 格的假漂移 vs 保守口径 Δ=+0.9 格。
   如果 eng-flue 用"通道内质心"验收，他很可能在机制还没真正生效时就误判"已经流了"。
3. **P=0 对照臂在这个几何里是无效对照。** 因为 `ductFlow` 对开放几何本来就不启用（§5.1 第 3 条），
   P=0 与 P=0.7 逐位相同。**真正有区分度的对照臂是 `noheat`（churn 39,566 vs 239 万）**
   —— 它证明热驱动确实是运动来源。等 eng-flue 的开口机制上线后，P=0/键名置零的对照臂
   才会变得有意义（我的 `zeroMechanisms()` 用键名正则动态匹配，他新增参数我自动能关）。
4. **渲染层假象的预防措施已就位**：我的渲染把抖动时间项**固定为 t=0**（`_qa_shot.js` 注释），
   所以墙面/气体纹理跨帧完全稳定，逐帧差分只反映真实位移。如果他出图时抖动每帧都在变，
   "看起来在动"可能只是抖动噪声 —— 交叉对照时用我的 `qa-flue-clean-*` 系列比。
